# Портфолио: автоматизация BIM / Revit

Операторская автоматизация Autodesk Revit: **сжатие workshared-моделей**, переименование / апгрейд года / relink парка разделов, еженедельный health-аудит, единицы / уровни-оси, оповещения по папкам обмена.

Я пишу **task-скрипты и Windows-toolkit’и** (выбор моделей → прогон → цветной Excel). [Revit Batch Processor](https://github.com/bvn-architecture/RevitBatchProcessor) (RBP) — открытый батч-хост для Revit API, не мой продукт; не каждый кейс его использует (см. [Сторонние компоненты](#сторонние-компоненты)).

## Быстрый старт (3 шага)

Для кейсов с Revit API (01, 02, 03, 05, 06). Кейс 04 — отдельный PowerShell-наблюдатель, см. его README.

1. **Подготовьте ПК:** Windows, PowerShell, год Revit = году моделей, [Revit Batch Processor](https://github.com/bvn-architecture/RevitBatchProcessor). Скопируйте `src/` кейса рядом и поправьте `servers.cfg` (в репо — placeholder-хосты Revit Server).
2. **Соберите список моделей** пикером кейса (`choose_models_path.cmd`; кейс 05 — `Сжатие.vbs`, новое окно кейса 06 — `Операции с моделями.vbs`).
3. **Запустите задачу** в RBP (например, `health_check.py`) **сначала на тестовой локальной копии**, затем смотрите отчёт (CSV / цветной XLSX). Точные настройки RBP — в README каждого кейса.

## Проблема → подход

**Типовая неделя:** пришла обновлённая АР; нужно держать в согласованности БФ и множество разделов (единицы, здоровье модели, уровни/оси). Хранилищам ещё нужно периодическое сжатие. Перенос парка (имена / год / связи) нужно ставить по этапам, чтобы хост не сохранить раньше связей.

Вручную это не масштабируется. Toolkit’и:

1. Собирают список моделей (папка / файлы / Revit Server)
2. Гоняют задачу Revit API (батч-хост или отдельное окно)
3. Отдают отчёты **GREEN / YELLOW / RED** — или вес до/после для Compact
4. Пишут в модель только там, где риск понятен (единицы; уровни/оси БФ; Compact с явным режимом; model ops после Save job) — без «автокоординации»

## Масштаб / контекст проекта

Контекст проекта, под который писались скрипты (обезличено). Цифры описывают типовую нагрузку, а не гарантированный результат.

| Пункт | Контекст | Эффект |
|-------|----------|--------|
| Недельный каскад | ~5–6 БФ (БФ↔АР), затем до ~80 разделов (↔БФ) | Одна сессия отчёта на волну вместо ручной сверки уровней/осей в каждой модели |
| Операции с парком | ~50+ моделей, UNC / `RSN://` | Одно задание ведёт проходы detach / Save As / перенос / relink (новое окно — прототип) |
| Units / RSN | Модели Revit Server | Один батч точности Length по диску и `RSN://` |
| Сжатие | Глубокий режим на UNC/файлах; глубокий RSN экспериментальный | Один незанятый прогон на длинных списках (например ~125 моделей); дельта размера часто мала (61,03→61,01 МБ на прогоне из 2 моделей) |
| Health Check | Read-only аудит workshared | Один цветной XLSX и CSV по связям и метрикам по хабу |
| Levels & Grids | MVP; пилот в ожидании | Сначала каскад БФ, затем разделы — до массового Apply |
| Оповещения FTP | Папки обмена | Опрос по расписанию → push без ручного FTP |

## Правила безопасности

Автоматизация, которая ломает федеративную модель, хуже отсутствия автоматизации.

- **Audit** никогда не делает Save / Sync / Relinquish
- **Apply** — отдельный скрипт / явный список (например, только БФ)
- **Compact** — запись: быстрый через Create New Local; глубокий открывает хранилище с Audit и сохраняет то же хранилище со сжатием (без Detach). Что чужие локальные файлы не ломаются — задумано, не проверено. Глубокий RSN требует патч RBP v4 и экспериментальный.
- **Model ops** пишет только после Save job; Detach — локальный буфер апгрейда, не боевая централь
- Координаты, PBP, Survey, True North, Shared Coordinates — **не трогаем автоматом**
- Допуски обязательны, иначе ложные RED

Подробнее: [docs/SAFETY.ru.md](docs/SAFETY.ru.md)

## Scope / что не покрыто

Чего в репозитории **нет**:

- **Нет C# / .NET add-in для Revit.** Только IronPython-задачи + PowerShell / WinForms.
- **Нет Dynamo** (ни графов, ни скриптов).
- **Нет AI / LLM / машинного обучения.**
- **Нет CI в репозитории** (только ручная проверка; см. примечание в начале).
- **Скриншоты** окна сжатия, листов Excel «Модели» и «Сводка», и листа проверки связей лежат в `docs/img/`. Демо-записей нет.
- **Нет автоматизации Navisworks** (только черновик матрицы допусков) и нет интерфейса внутри Revit — окна оператора внешние (WinForms / `.vbs`).
- Это не универсальный BIM-фреймворк: кейсы закрывают один процесс (обслуживание парка workshared / Revit Server и аудиты).
- Часть имён файлов и комментариев в кейсах 01, 05, 06 — на русском (`Сжатие.vbs`, `служебное/`); перевод в планах.
