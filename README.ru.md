Операторская автоматизация Autodesk Revit: **сжатие workshared-моделей**, переименование / апгрейд года / relink парка разделов, еженедельный health-аудит, единицы / уровни-оси, оповещения по папкам обмена.

Я пишу **task-скрипты и Windows-toolkit’и** (выбор моделей → прогон → отчёт в Excel). [Revit Batch Processor](https://github.com/bvn-architecture/RevitBatchProcessor) (RBP) — открытый батч-хост для Revit API, не мой продукт; не каждый кейс его использует (см. ## Быстрый старт (3 шага)

Для кейсов с Revit API (01, 02, 03, 05, 06). Кейс 04 — отдельный PowerShell-наблюдатель, см. его README.

1. **Подготовьте ПК:** Windows, PowerShell, год Revit = году моделей, [Revit Batch Processor](https://github.com/bvn-architecture/RevitBatchProcessor). Скопируйте `src/` кейса рядом и поправьте `servers.cfg` (в репо — placeholder-хосты Revit Server).
2. **Соберите список моделей** пикером кейса (`choose_models_path.cmd`; кейс 05 — `Сжатие.vbs`, новое окно кейса 06 — `Операции с моделями.vbs`).
3. **Запустите задачу** в RBP (например, `health_check.py`) **сначала на тестовой локальной копии**, затем смотрите отчёт (CSV и отчёт в Excel). Точные настройки RBP — в README каждого кейса.

## Проблема → подход

**Типовая неделя:** пришла обновлённая АР; нужно держать в согласованности БФ и множество разделов (единицы, здоровье модели, уровни/оси). Хранилищам ещё нужно периодическое сжатие. Перенос парка (имена / год / связи) нужно ставить по этапам, чтобы хост не сохранить раньше связей.

Вручную это не масштабируется. Toolkit’и:

1. Собирают список моделей (папка / файлы / Revit Server)
2. Гоняют задачу Revit API (батч-хост или отдельное окно)
3. Отдают отчёты в Excel со светофором (**GREEN / YELLOW / RED**) — или вес до/после для Compact
4. Пишут в модель только там, где риск понятен (единицы; уровни/оси БФ; Compact с явным режимом; model ops после Save job) — без «автокоординации»

## Масштаб / контекст проекта

Типовой контекст (обезличенные примеры). Цифры описывают обычный размер батча на многораздельном проекте.

| Пункт | Контекст | Эффект |
|-------|----------|--------|
| Недельный каскад | ~5–6 БФ (БФ↔АР), затем до ~80 разделов (↔БФ) | Примерно в 4–5 раз быстрее, чем вручную; одна сессия отчёта на волну |
| Операции с моделями | ~50+ моделей, UNC / `RSN://` | Примерно в 4–5 раз быстрее, чем вручную; одно задание ведёт проходы detach / Save As / перенос / relink |
| Units / RSN | Модели Revit Server | Примерно в 4–5 раз быстрее, чем вручную; один батч точности Length по диску и `RSN://` |
| Сжатие | Рабочие модели; глубокий RSN на ограниченном числе прогонов | Примерно в 4–5 раз быстрее, чем вручную; длинные списки (например ~125 моделей) в одном прогоне; дельта размера часто мала (61,03→61,01 МБ на прогоне из 2 моделей) |
| Health Check | Read-only аудит workshared | Примерно в 4–5 раз быстрее, чем вручную; один отчёт в Excel и CSV по хабу |
| Levels & Grids | MVP (Apply только для БФ) | Примерно в 4–5 раз быстрее, чем вручную; каскад БФ, затем разделы |
| Оповещения FTP | Папки обмена | Опрос по расписанию → push без ручного FTP |

## Правила безопасности

Автоматизация, которая ломает федеративную модель, хуже отсутствия автоматизации.

- **Audit** никогда не делает Save / Sync / Relinquish
- **Apply** — отдельный скрипт / явный список (например, только БФ)
- **Compact** — запись: быстрый через Create New Local; глубокий открывает хранилище с Audit и сохраняет то же хранилище со сжатием (без Detach). Глубокий RSN требует патч RBP v4 (`RSN_PATCH_PS_v4`); проверен на ограниченном числе прогонов.
- **Операции с моделями** пишут только после Save job; Detach — локальный буфер апгрейда, не боевая централь
- Координаты, PBP, Survey, True North, Shared Coordinates — **не трогаем автоматом**
- Допуски обязательны, иначе ложные RED

Подробнее: [docs/SAFETY.ru.md](docs/SAFETY.ru.md)

## Стек и границы применения

- **Revit API:** task-скрипты (IronPython) через [Revit Batch Processor](https://github.com/bvn-architecture/RevitBatchProcessor); операторские окна на **PowerShell** и **WinForms**; отчёты **OpenXML** в Excel (без Excel COM на UNC).
- **Фокус:** workshared и Revit Server (`RSN://`) — read-only аудиты, контролируемые пакетные записи (единицы, уровни/оси на БФ, Compact, поэтапные операции с моделями).
- **Платформа:** Windows. Кейс 04 — опрос FTP и push на телефон (ntfy / Telegram).
- **Документация:** примеры в `samples/`, скриншоты в `docs/img/`, безопасность в [docs/SAFETY.ru.md](docs/SAFETY.ru.md).
