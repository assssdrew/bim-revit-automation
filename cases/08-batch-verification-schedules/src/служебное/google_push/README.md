# Google: обновление таблицы задания

1. Создайте пустую Google-таблицу на проект. Ссылку вставьте в окне «Задание» (для чата проектировщикам).
2. В таблице: **Расширения → Apps Script**. Вставьте `Code.gs`. Секрет лучше задать в **Настройки проекта → Свойства скрипта → `PUSH_SECRET`** (длинная случайная строка); запасной вариант — заменить `REPLACE_ME_WITH_LONG_RANDOM_SECRET` в `var PUSH_SECRET`. Реальный секрет в git не коммитить.
3. **Развернуть → Новое развёртывание → Веб-приложение**. Кто имеет доступ: **Только я** (или вся организация). Выполнять как: **Я**. Доступ: **Все**.
4. В **Управление развёртываниями** откройте развёртывание типа **Веб-приложение** (не «Библиотека»). Скопируйте **URL** (`…/macros/s/…/exec`).
5. На **Public** создайте файл (из `google_push.cfg.example`):

   `C:\Users\Public\Documents\doc\script\rbp\batch_verification_schedules\служебное\google_push\google_push.cfg`

   - `webapp_url=` URL веб-приложения
   - `secret=` **то же**, что свойство скрипта `PUSH_SECRET` (или `var PUSH_SECRET` в `Code.gs`). **Не** подставляйте «Идентификатор развертывания».

6. Проверка без Revit: `служебное\google_push\проверить_google.ps1` → `OK POST` (если пишет «старая версия Code.gs» — вставьте новый Code.gs и сделайте новую версию развёртывания).
7. После «Собрать задание» скрипт отправит листы **Сводка** и **ЭОМ…ХС** (значения, цвета, ширины колонок, объединение шапки, группы строк «+» как в Excel). Лист **Динамика** в Google не попадает и скрывается, если был.

## Веб-страница для проектировщиков (только просмотр)

Страница показывает листы разделов (ЭОМ, СС, ОВ, ПД, ПТ, ВК, ОТ, ХС — все видимые листы, кроме «Сводка» и «Динамика») и «Сводку» из этой же таблицы. Раскрытие строк у каждого своё (хранится в браузере, `localStorage`), в таблицу ничего не пишется, **вход в Google не нужен**. Из-за общего состояния групп и защиты листов в самой таблице (группы не раскрываются, `onEdit` у анонимов не работает) проектировщикам лучше давать именно эту ссылку, а доступ к таблице не расширять.

Что внутри: `Code.gs` (`doGet` + `viewerGetSection` / `viewerGetSummary` — только чтение; `doPost` и отправка данных не менялись) и `Viewer.html`. Таблицу `doGet` берёт тем же способом, что `doPost` (`SpreadsheetApp.getActiveSpreadsheet()`, скрипт привязан к таблице).

### Публикация (один раз)

1. В таблице: **Расширения → Apps Script**. Вставьте актуальный `Code.gs` (заменив прежний, секрет `PUSH_SECRET` остаётся в свойствах скрипта).
2. Слева у списка файлов **+ → HTML**, имя ровно **`Viewer`** (расширение `.html` добавится само), вставьте содержимое `Viewer.html`.
3. **Развернуть → Новое развёртывание → тип «Веб-приложение»** (это **отдельное** развёртывание, развёртывание для отправки данных не трогайте). Описание: «Просмотр отчёта». **Выполнять как: Я** (владелец таблицы). **У кого есть доступ: Все** (именно «Все», не «Все в аккаунте Google»). **Развернуть**, при первом запросе разрешите доступ.
4. Скопируйте **URL веб-приложения** (`https://script.google.com/macros/s/…/exec`) — это ссылка для проектировщиков.
5. Проверка: откройте URL в окне инкогнито (без входа в Google) — должна открыться страница с вкладками разделов.

Если в Google Workspace пункта «Все» нет — администратор домена запретил публичные веб-приложения; нужен личный аккаунт владельца или разрешение администратора.

### Ссылки для проектировщиков

- Общая: `https://script.google.com/macros/s/…/exec` (откроется первый раздел).
- Сразу нужный раздел: `…/exec?section=ЭОМ`, `…/exec?section=ВК`, … ; «Сводка» — `…/exec?section=Сводка`. Кириллицу браузер подставит сам; в чат ссылку можно копировать кнопкой «Ссылка» на странице.

### Что умеет страница

- Вкладки разделов и отдельная вкладка «Сводка» (плоская таблица, цвета ячеек, закреплены шапка и первый столбец).
- Дерево как на листе раздела: модель → спецификация → элементы, «+»/«−» на каждом узле, кнопки уровней **1 / 2 / 3** (по умолчанию 2, как после отправки), «Развернуть всё» / «Свернуть всё», поиск по имени модели.
- Те же столбцы и цвета, что на листе; шапка закреплена. Раздел на ~2000 строк открывается за доли секунды, данные читаются одним обращением.
- «Обновить» перечитывает таблицу (данные — как после последней отправки задания).

### Дата данных и автообновление

- Каждая **успешная** отправка данных (`doPost`) записывает время в свойство скрипта `LAST_PUSH_MS` (неудачные отправки его не меняют; сбой записи свойства отправку не роняет). Остальная логика `doPost` не менялась.
- В шапке страницы: «Данные от ДД.ММ.ГГГГ ЧЧ:ММ» (время по Asia/Saigon). Пока выгрузки с этой версией `Code.gs` не было — «Время выгрузки неизвестно» (появится после следующей отправки).
- Раз в 5 минут страница вызывает лёгкую `viewerGetVersion` (читает только это свойство, листы не трогает). Если время новее показанного — вверху появляется оранжевая плашка «Данные обновились — нажмите, чтобы обновить». Клик (или кнопка «Обновить») перечитывает текущий раздел или «Сводку» **без перезагрузки страницы**: раздел, раскрытие строк (`localStorage`), поиск и прокрутка сохраняются.
- Пока вкладка браузера скрыта, проверок нет; при возврате на вкладку проверка выполняется сразу. Ошибки проверки молча игнорируются (без окон и сообщений).
- Страница по-прежнему ничего не пишет в таблицу; на сервер уходят только `viewerGetSection`, `viewerGetSummary`, `viewerGetVersion`.

### Обновление страницы после правок кода

Код один на оба развёртывания, но каждое работает на **своей версии**: после любой правки `Code.gs` / `Viewer.html` выпустите **«Новая версия» в обоих** — **Развернуть → Управление развёртываниями →** развёртывание **для отправки данных** (чтобы `doPost` начал записывать время выгрузки) **и** развёртывание **«Просмотр отчёта»** (страница, `viewerGetVersion`) **→ карандаш → Версия: Новая версия → Развернуть.** URL не меняются. Пока старая версия отправки не обновлена, страница показывает «Время выгрузки неизвестно» и не узнаёт о новых данных.

### Замечания

- Любой, у кого есть ссылка, видит весь отчёт (разделы и сводку); менять ничего не может. Секрет `PUSH_SECRET` на страницу не попадает.
- Вверху страницы Google может показывать свою серую полоску о том, что приложение создано пользователем Apps Script, — это нормально.
- Если проектировщики пользуются только страницей, доступ к самой таблице «по ссылке» можно не давать: задайте `LINK_SHARING = ''` в `Code.gs` (и закройте доступ в «Настройках доступа» таблицы). Страница работает от имени владельца.
- Открытие URL развёртывания для отправки данных тоже покажет страницу; `?ping=1` отвечает `ok`, как раньше (`проверить_google.ps1`).

После обновления `Code.gs` в таблице нужно **Развернуть → Управление развёртываниями → изменить → новая версия** (иначе веб-приложение останется на старом коде).

Файл `google_push.cfg` не коммитить в git (секрет).

Повторная отправка только из `google_push_payload.json` (без xlsx):

`push_google.ps1 -PayloadOnly -PayloadPath "отчеты\служебные\<время прогона>\google_push_payload.json"` (JSON лежит в служебной папке прогона; папки старше 30 дней удаляются автоматически)

## Как устроена отправка (после исправлений)

- Каждая отправка **полностью пересоздаёт** листы: удаляет старые строки (вместе с группами «+»), снимает объединения, пишет значения и формат заново. Повторная отправка даёт тот же результат; ошибки «row group depth cannot exceed 8» больше нет.
- Разделы, которых нет в этой выгрузке (замечаний не осталось), очищаются и получают пометку «Замечаний нет», чтобы Google не расходился с xlsx.
- Значения пишутся как текст (даты `2026-10-05`, `007`, строки на `=` не превращаются в даты/числа/формулы); целые числа — числами.
- Ответ скрипта — JSON `{"ok":true,...}` или `{"ok":false,"error":"..."}`. Клиент считает успехом только `ok:true` (или ровно `ok` от старого Code.gs). HTML-страница, `forbidden`, `error:`, пустой ответ и HTTP-ошибки — отказ, UI покажет «Google не обновлён: …».
- Таймаут запроса 5 минут, до 3 попыток при сетевых сбоях/5xx (повтор безопасен: скрипт под блокировкой и идемпотентен).
- Если в `Code.gs` ещё лежит старая версия (ответ `ok` без JSON) — клиент работает, но предупреждает об обновлении.
- Выборочная выгрузка: в payload есть `partial` и явный список `clear`; листы, которых нет ни в `sheets`, ни в `clear`, не меняются. Формат `dim: true` у ячейки — серый шрифт (пара «модель + спецификация» в этой сборке не проверялась). Для серого шрифта `Code.gs` нужно переопубликовать.

## Лист раздела в Google: уровни 1/2/3

В ячейке **A1** каждого листа раздела — выпадающий список 1/2/3 (как кнопки уровней в Excel): 1 — только модели, 2 — спецификации (по умолчанию после каждой отправки), 3 — элементы. Смена значения срабатывает через простой триггер `onEdit` (устанавливать ничего не нужно, нужен лишь новый Code.gs и новая версия развёртывания). Заметка перенесена в B1. Ширины колонок — по содержимому (считаются в `assignment_xlsx.ps1`, одинаково для xlsx и Google).

## Доступ к таблице «у всех со ссылкой»

Каждая отправка проверяет доступ и, если нужно, ставит **«Все, у кого есть ссылка» → Читатель** (константа `LINK_SHARING` в `Code.gs`: `'VIEW'`, `'EDIT'` или `''`, чтобы не трогать доступ). Если кто-то закрыл доступ, следующая отправка его вернёт. В ответе скрипта поле `sharing`: `ok` или `error: …`; ошибка доступа не отменяет обновление данных.

Один раз после вставки нового `Code.gs`:
1. В редакторе Apps Script выберите функцию **`setLinkSharing`** → **Выполнить** → разрешите доступ к Google Диску (скрипту нужно новое право, из веб-приложения оно само не запрашивается).
2. **Развернуть → Управление развёртываниями → изменить → новая версия.**

Ограничения Google: доступ ставит тот, у кого есть право управлять файлом (владелец таблицы; веб-приложение запускается «от имени меня» — этот же аккаунт должен быть владельцем). В Google Workspace (например, домен организации) администратор может запретить доступ по ссылке — тогда `sharing` вернёт ошибку, и открыть доступ можно только настройками домена или вручную («Настройки доступа» в таблице).

## Проектировщики: «+» в группах и список 1/2/3 в A1

Что нашлось в коде. Защит листов и диапазонов (`protect`) `Code.gs` **не ставит**. А вот прежняя `ensureLinkSharing_` при `LINK_SHARING = 'VIEW'` вызывала `setSharing(ANYONE_WITH_LINK, VIEW)` и тем самым **понижала** уже выставленный по ссылке «Редактор» до «Читателя»: у читателя нет права менять A1 (список уровней и `onEdit` не работают), в режиме просмотра работа с группами ограничена. Теперь доступ **только повышается**: `LINK_SHARING` — минимум, более широкий доступ не трогается (доступ по домену с правкой тоже, с пометкой в `sharing`).

Что сделать после переопубликации:
1. Если после этого у проектировщиков по ссылке по-прежнему «Читатель» (скрипт уже понизил) — один раз выставьте вручную «Все, у кого есть ссылка → **Редактор**» (или задайте `LINK_SHARING = 'EDIT'` и отправьте задание: скрипт повысит доступ сам). Редактор по ссылке означает, что любой со ссылкой может менять таблицу; данные разделов при следующей отправке перезаписываются.
2. Запустите в редакторе Apps Script функцию **`diagnoseAccess`** (Выполнить) и посмотрите журнал: доступ по ссылке, защиты листов/диапазонов, есть ли список в A1. Если кто-то вручную защитил лист (Данные → Защищённые листы и диапазоны), редакторы без права на защиту не смогут раскрывать группы строк и выбирать уровень — защиту надо снять или разрешить им редактирование.
3. Запасной путь для режима просмотра: **Вид → Группа → Развернуть/Свернуть все группы строк** (подсказка есть в заметке B1 на листах разделов).

## Адрес на проект

Адрес веб-приложения и секрет каждого проекта задаются на вкладке «Задание» окна и хранятся в `отчеты\проект\google_<проект>.cfg` (строки `webapp_url=` и `secret=`; папка отчётов в `.gitignore`). Общий `google_push.cfg` в этой папке — запасной вариант: в него отправка идёт только после подтверждения «У проекта нет своего адреса Google. Отправить в общую таблицу из google_push.cfg?» (по умолчанию «Нет»). Проверка связи: кнопка «Проверить» в окне или `проверить_google.ps1` (для общего cfg).
