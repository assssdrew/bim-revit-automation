# Сравнение фильтров спецификаций двух проектов

Нужно, чтобы убедиться, что правки фильтров не внесли ошибок относительно исходных спецификаций (например, Никольская РД).

## 1. Выгрузить фильтры (только чтение)
**`служебное\разработка\инструменты\Выгрузить фильтры спек.bat`** — перетащите на него файлы `.rvt`, **папку** (поиск по всем вложенным папкам) или **текстовый список** `.txt` (один путь на строку; несколько путей в строке или в аргументе — через «;»). Если перетащить сразу десятки файлов из поиска проводника, командная строка их не вмещает и появляется запрос пути: вставьте туда папку или txt. Из папки не берутся резервные копии Revit (`имя.0001.rvt`), сводные (`SVOD`/`СВОД`) и каталоги `Резерв*`, `Архив*`, `Archive*`, `Backup*`, `_backup*`, `Old`, `Стар*`, `OLD_*`, а также папки с именем-датой (`2026-10-19`). В такие папки скрипт не заходит. Одинаковое имя модели в нескольких местах берётся один раз (короткий путь вне этих папок), остальные пишутся как дубль. В итоге строки «Найдено моделей: N» и «Пропущено папок резервных копий: M». Перед запуском нужно ответить «д». Явно указанный файл `.rvt` (в аргументе или в txt) берётся как есть, даже если это сводная. Через Revit Batch Processor (как остальные кнопки; `RSN://` поддерживается) открывается каждая модель, **ничего не меняется, не сохраняется и не пишется в Google**. Модели разных версий Revit идут отдельными проходами.

Результат — `отчеты\операции\дамп_фильтров_<время>\фильтры_<имя модели>.txt` (UTF-8): `Спецификация <TAB> Поле фильтра <TAB> Условие <TAB> Значение`, как `фильтры_спецификаций.txt`, и рядом `спеки_<имя модели>.txt` — только имена спецификаций, по одному на строку (удобно сравнивать состав). Выгружаются **все** спецификации модели (кроме шаблонов, ведомостей изменений и ключей); спека без фильтров — строка «(нет фильтров)». Только часть спек: `dump_schedule_filters.ps1 ... -NameContains "Пустые|Без знач"`. Скрипт Revit — `dump_schedule_filters.py`.

## 2. Сравнить две выгрузки
**`служебное\разработка\инструменты\Сравнить фильтры спек.bat`** — перетащите два файла: первым «было» (исходные, Никольская), вторым «стало» (наши). Либо `compare_filter_dumps.ps1 было.txt стало.txt [-Swap] [-OutCsv файл.csv]` (`-Swap` — если порядок перепутан).

- Спеки сопоставляются по **имени без префикса «П»** (регистр, вид пробелов и опечатка «значния/значения» не важны). Если имени не нашлось, а номер (например `5.1`) на каждой стороне остался один — сопоставляются по номеру, в «Примечании» записано прежнее имя.
- Порядок фильтров внутри спеки не сравнивается.
- Таблица (CSV для Excel, `отчеты\операции\сравнение_фильтров_<время>.csv`): Номер; Спецификация; Изменение; Было; Стало; Примечание. «Изменение»: **добавлено**, **удалено**, **изменено: условие / значение / условие и значение / поле**, а также **спека только в «было»** и **спека только в «стало»** (отдельные строки, в колонке — число фильтров).
- Листы с одинаковым именем в одной модели в выгрузке неразличимы и считаются одной спекой.

## Примечание: пути с кириллицей в IronPython 2.7
`os.path.isdir`/`os.path.isfile`/`os.makedirs` в IronPython 2.7 на путях с кириллицей (`…\служебное\`, `…\отчеты\`) ошибаются: проверка «папка есть» отвечает «нет», а `os.makedirs` падает `[WindowsError]`, хотя папку уже создал `dump_schedule_filters.ps1` до запуска RBP. В `dump_schedule_filters.py` и `export_schedules.py` папка создаётся через .NET (`System.IO.Directory.CreateDirectory` — идемпотентно, понимает кириллицу), существование файла настроек проверяется через `System.IO.File.Exists`.

## Если выгрузка упала

Скрипт `dump_schedule_filters.py` при любой ошибке пишет полный traceback, шаг (чтение настроек / создание папки / чтение спецификации / запись) и путь модели
в `%TEMP%\dump_schedule_filters_error.txt` (путь без кириллицы; файл дописывается) и в лог RBP (строка `DUMP ERROR`). Пришлите этот файл.
Все файловые операции скрипта идут через .NET (System.IO), без `open()`/`os.*`.
