# Тесты цепочки xlsx → Google (без Windows, Revit, Excel, Google)

```
cd tools/batch_verification_schedules/служебное/разработка
PWSH=/путь/к/pwsh python3 -m unittest discover -s tests -v     # pwsh опционален, без него часть тестов пропускается
node tests/code_gs_mock_test.js                                # мок Code.gs: многократная отправка и т.д.
python3 tests/check_xlsx.py <задание.xlsx> [google_push_payload.json]   # проверка реального файла
powershell -NoProfile -File tests\ps_unit.ps1                  # на Windows PowerShell 5.1: юнит-проверки функций
```

* `check_xlsx.py` — проверка валидности xlsx (zip, порядок XML-элементов, одиночные merge, `t="str"`, openpyxl) и совпадения с payload (текст ячеек, цвета).
* `code_gs_mock_test.js` — имитация SpreadsheetApp: 12 отправок подряд, идемпотентность, цвета, типы значений, secret, битый payload, очистка разделов. Это модель, а не настоящий Google: поведение `deleteRows`/групп нужно подтвердить на настоящей таблице (см. отчёт).
* `test_chain.py` — сборка xlsx настоящим `build_assignment.ps1` (OpenXml dll работает и на Linux под pwsh) + сквозной `push_google.ps1` против локального мок-сервера (HTML, `error:`, `ok:false`, 404, legacy `ok`).
* `test_partial_state.py` — состояние «Выборочно» одним файлом `<история>_состояние.txt`: цепочка «Всё → Выборочно (×5, незагруженная связь, удалённые спецификация и модель, без каталога) → Всё → Динамика» совпадает с эталоном `tests/baseline_partial` (снят на коде фазы 6; `make_baseline.py --partial`) — и в новом формате, и с прежними тремя файлами посреди цепочки, и после переноса; перенос (резервная копия, `.migrated_<дата>`, повторный запуск, без копии — ничего, откат), списки «Выборочно» до и после; пустой `[inproject]`/`[summary]` = «ни одна», раздела нет = «все».
* `test_baseline.py` — эталон режима «Всё» (`tests/baseline`): сборка → исправлено → вернулось → убрали спецификацию, плюс старые история/журнал без ложных «Новое»/«исправлено». Перезапись эталона — только осознанно (`make_baseline.py`).
* `test_export_partial.py` — `main()` выгрузки из Revit на подставном API: «Всё» без изменений, «Выборочно» (фильтр спецификаций и строк, пары, незагруженные связи, каталог); пишется только `export.txt` (разделы сравниваются с прежними файлами).
* `test_partial.py` — сборка в режиме «Выборочно» (буфер, парное закрытие замечаний, засев из старых файлов, удалённые спецификации и модели, свежесть, частичный payload) и логика списков окна.
* `test_ironpython_compat.py` — скрипты для Revit (IronPython 2.7: `export_schedules.py`, `insert_schedules.py`, `служебное/*.py`) без конструкций только для Python 3: `re.sub/split(..., flags=)`, f-строки, `casefold`, `os.makedirs(exist_ok=)`, `open(encoding=)` и т. п. (разбор AST).
* `test_compare_filters.py` — выгрузка фильтров всех спецификаций (`dump_schedule_filters.py` на подставном Revit API: формат, только чтение, числовые значения, шаблоны) и сравнение двух выгрузок (`compare_filter_lib.ps1`: добавлено/удалено/изменено, спеки только в одном файле, префикс «П», сопоставление по номеру, реальный дамп).
* `test_revit_versions.py` — версия Revit по моделям: BasicFileInfo в Compound File (малый и обычный поток, смещения), RSN:// по servers.cfg, остановки (разные версии, не определена, общий файл новее), сценарий «общий 2024, модели RSN 2022», проводка на всех шагах.
* `test_audit_fixes.py` — итог «Сводная/Разделы» (код RBP и колонка «Ошибка»), префикс проекта в «Задании» (PROJ без изменений, другой префикс, чужой префикс), версии Revit в инструментах, RSN:// у общего файла, подсчёт при open_all.
* `test_portability.py` — плоская раскладка корня, `.gitignore`, пример `google_push.cfg.example` без значений, `-SelfCheck` (в т. ч. из копии в пути с кириллицей и пробелами), корень отчётов, `.vbs`/`.bat` без зашитых путей (`pushd`), нет IP/`C:\Users`, один диалог выбора папки.
* `test_two_tabs.py` — окно из двух вкладок: чтение старых настроек (ничего не теряется), один режим вставки из прежних двух, «В сводную» и «В разделы» включаются вместе после распределения (путь сводной и SummaryDone «В разделы» не выключают), источник «Модели» из прежнего списка, проверки текста окна.
* `test_projects.py` — проекты: смена PROJ↔SITE не смешивает пути, выбор, Google, журнал; перенос старого ui_settings.txt в проект; журнал на проект; статус с проектом и Google; без проекта кнопки неактивны (в test_two_tabs).
* `test_google_per_project.py` — адрес Google на проект: разные проекты — разные адреса, без адреса вопрос (по умолчанию «Нет»), общий cfg не берётся молча, секрет не в статусе/логе и не в git.
* `test_samplesite_sections.py` — SampleSite: разделы АВТ/ХЦ (код в имени, PRK, запасной вариант по папке; чужой код вроде XYZ/BF/GU в таблицу не входит), справочник дописывается один раз, Google без полей адреса/секрета (статус из cfg, cfg не переписывается), выделение узла дерева «Выборочно», отчёты по папкам проектов, миграция не трогает папки проектов, АВТ3 без изменений.
* `test_report_xlsx.py` — отчёт прогона в xlsx без Excel: файл — zip, 4 листа, данные как в CSV, свёрнутые группы, ошибка записи; в коде отчёта нет COM/Start-Process.
* `test_selection_file.py` — «В проекте» только в `[inproject]` настройки проекта: одиночные галочки и массовые действия («Выделить всё», «Снять всё», «Распределить») держатся в памяти до «Сохранить» / «Сохранить как новый проект» / «Отменить», восстановление при загрузке, неизвестные спеки не теряются, подсказка без `[inproject]`, «Взять выбор из сводной», файла выбора больше нет.
* `test_state_migration.py` — перенос прежнего `выбор_<проект>.txt` в `[inproject]`: только файл выбора, пустой `[inproject]`, совпадают, различаются (остаётся `[inproject]`, разница в журнал), повторный запуск, несколько проектов, без резервной копии ничего не пишется; резервная копия `проект\_backup_<время>` (без прежних копий, с историей и журналом) до записи и вне автоочистки; открытие проекта в окне и строка в статусе.
* `test_excel_own_process.py` — закрывается только свой Excel (PID из запуска / hwnd); «чужой» EXCEL.EXE после старта не трогается, seed удаляется, PID неизвестен — ничего не убивается (на Linux «Excel» — копия sleep под именем EXCEL).
* `test_startup_view.py` — открытие окна: кэш спецификаций / пустая таблица с подсказкой, ширины столбцов, закрытие своего Excel и ссылка «Открыть CSV», режим вставки по умолчанию и подтверждение «Заменить все».
* `test_section_catalog.py` — справочник «раздел → номера/категории», «Распределить» (категории, номера, диапазоны, «кроме», пустая модель, неизвестный раздел, ошибки файла), подсветка, кэш категорий; «Распределить» не открывает модели, пробная вставка под «Посчитать элементы».
* `test_dist_groups.py` — «Распределение»: группировка 203 спецификаций SampleSite (`данные/samplesite_template_specs.tsv`) в 80 групп (группа = имя без хвоста), подпись «(основная)», «В проекте» по спецификациям, колонка «Сводная», RSN://-модели.
* `test_project_config.py` — настройка проекта (`project_config.ps1`): группы спецификаций, фильтр инженерных моделей по коду раздела (кириллица/латиница/регистр/без ложных срабатываний на IOS/ИОС/ВИС/TASK/сводную), «В проекте», дерево ⊞/⊟, префикс и имя файла настройки, запрет файла вместо папки, отказ при пустом пути, ячейки/агрегаты/клик/цвета, свёрнутая и раскрытая таблица, файл с кириллическим путём, паритет с прежними пакетами (данные `tests/project_fixture.py`) (ПД 38, ОВ 55, ВК 53, ОТ 55, ЭОМ 35), подстановка стадии ({ШИФР} не поддерживается).
* `test_insert_plan.py` — план вставки (`plan.txt` от окна) против прежнего разбора файла настройки в `insert_schedules.py`: PROJ и SampleSite, «В сводную» и «В разделы», initial/add_diff/replace и автопереход на первичную, модели без кода, по папке, не размеченные, ИТП, исключённые RG_ORG_BF_/GU_, пустые `[inproject]`/`[summary]`, без `stage=`; повреждённый план — запасной путь.
* `test_export_result.py` — итог выгрузки одним файлом `export.txt`: оба формата читаются одинаково, `<история>_каталог.txt` прежнего формата, задание/payload/история/журнал/буфер из `export.txt` те же, что из прежних трёх файлов; чтение один раз за сборку.
* `test_insert_project.py` — `insert_schedules.py` (набор из проекта, префикс стадии, профиль, режим предзаполнения с откатом) и `read_template_specs.py` на подставном Revit API.
* `test_project_dist_ui.py` — чтение результатов RBP и итоговый текст («Распределение»), статическая проверка подключения вкладки к окну.
* `test_viewer.py` — веб-страница просмотра отчёта (`служебное/google_push`: `doGet`/`viewerGet*` в `Code.gs` + `Viewer.html`): серверная часть на подставных листах только для чтения (`viewer_mock_test.js`, любой вызов записи роняет тест) и страница в Chromium через Playwright (`viewer_browser_test.js`: дерево, уровни, поиск, цвета, Сводка, состояние у каждого своё, 2000+ строк; дата данных, проверка новой выгрузки раз в N минут, плашка и обновление без перезагрузки, пауза при скрытой вкладке, тихие ошибки). Нужны node (и playwright с Chromium для браузерного теста — иначе он пропускается).
* `test_report_layout.py` — раскладка `отчеты\` (`report_layout.ps1`): миграция старых файлов без потерь и конфликтов, идемпотентность, автоочистка служебных папок (30 дней и `auxkeepdays`), продолжение истории/журнала/«Динамики» после переноса, проводка окна и служебных .bat на новые пути.
