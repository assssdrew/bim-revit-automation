Проверочные спецификации
=========================

Запуск: «Проверочные спецификации.vbs» в этой папке (см. «Установка на общий компьютер»).

Установка на общий компьютер
----------------------------
В корне только то, что нужно пользователю; всё остальное — в служебное\.
  Проверочные спецификации.vbs   — запуск
  ИНСТРУКЦИЯ.txt
  servers.cfg                    — адреса Revit Server (host|название|год REST)
  отчеты\                        — отчёты, история, настройка проекта (отчеты\проект) и журналы (отчеты\логи); создаётся сама
  служебное\                     — всё вспомогательное:
      скрипты\                   — рабочие скрипты окна и задач Revit (*.ps1, *.py)
      lib\                       — DocumentFormat.OpenXml.dll (сборка xlsx без Excel)
      google_push\, rbp_rsn_patch\, choose_models.ps1 — нужны окну;
      разработка\                — тесты, техническая документация и разовые/диагностические .bat BIM-менеджера
                                   (разработка\инструменты\); на общий компьютер не нужны

1. Скопируйте папку batch_verification_schedules в любое место (служебное\разработка можно не копировать). Подходит и сетевая папка (\\сервер\папка), и имя с кириллицей и пробелами: все пути считаются от расположения .vbs, ничего править не нужно.
2. Положите настоящий google_push.cfg (в git он не хранится: там секрет) сюда: служебное\google_push\google_push.cfg. Образец — google_push.cfg.example в той же папке: скопируйте его под именем google_push.cfg и впишите webapp_url и secret (подробнее — «Ссылка на Google-таблицу» ниже). Без этого файла всё работает, кроме автообновления Google-таблицы.
3. Адреса Revit Server — servers.cfg в корне, рядом с .vbs (строка host|название|год REST). Для моделей из папок servers.cfg не нужен.
4. Запустите «Проверочные спецификации.vbs» двойным щелчком. На компьютере должны быть Windows PowerShell 5.1 и Revit Batch Processor (см. «Перед первым запуском»).

Где что хранится на общем компьютере:
  • у каждого сотрудника (профиль Windows, %LOCALAPPDATA%\BatchRvt\batch_verification_schedules): настройки окна и пути, которые задаёт пользователь (общий файл спецификаций, папка моделей, сводная), файлы запуска Revit Batch Processor (run.cfg, списки моделей). Это не журналы.
  • общие для всех, кто запускает из этой папки: отчеты\ (итоговые xlsx, история, настройка проекта отчеты\проект\распределение_<префикс>.txt, журналы отчеты\логи). Не собирайте задание одновременно двумя сотрудниками.

Журналы этого скрипта — в отчеты\логи (кнопка «Логи» внизу окна): логи Revit Batch Processor именно этого запуска, google_push.log, partial_sets.log и файлы ошибок чтения шаблона / выгрузки фильтров. Файлы BatchRvt_*.log старше 30 дней удаляются автоматически. Настройки и папка логов по умолчанию у самого Revit Batch Processor не меняются: --log_folder передаётся только в командной строке запуска из этого окна (и служебных .bat этого инструмента). Запуски ModelOps, других инструментов и ручного окна RBP пишут логи как раньше, в том числе в %LOCALAPPDATA%\RevitBatchProcessor; эта папка скриптом не читается и не чистится.

Запуск с сетевой папки (UNC):
  • .vbs и окно работают с \\сервер\папка напрямую. Служебные .bat из служебное\разработка\инструменты\ сами подключают сетевую папку командой pushd (cmd не делает UNC текущей папкой) — запускайте двойным щелчком или перетаскиванием файлов моделей на .bat.
  • Политика выполнения скриптов менять не нужно: запуск идёт с -ExecutionPolicy Bypass.
  • Если Windows блокирует файлы (папка скачана из интернета или пришла в zip): до распаковки — свойства zip → «Разблокировать»; после — PowerShell: Get-ChildItem -Recurse "путь\batch_verification_schedules" | Unblock-File.
  • Предупреждение безопасности при открытии файла с сетевой папки: «Открыть» или добавьте сервер в зону «Местная интрасеть» (Свойства обозревателя → Безопасность). dll для xlsx при отказе загрузиться с сети копируется в профиль пользователя автоматически.
  • Проверка без Revit: служебное\скрипты\ui_schedules.ps1 -SelfCheck печатает найденные папки и «SELFCHECK OK» либо список недостающих файлов.

Для разработчика: тесты, README и техническая документация — служебное\разработка\.

Версия Revit: общий файл спецификаций держите в самой ранней версии и «Только чтение» (на каждом шаге версию определяют сами модели, а не имя; файл новее моделей или модели разных версий — запуск остановится).

Автотесты (служебное\разработка\tests) требуют PowerShell 7 (pwsh): без него около 100 тестов пропускается.

Что делает
----------
Копирует проверочные спецификации из одного файла Revit в модели ИОС.
Раздел определяется по имени файла (_OV_, _VK_, _EOM_ и т.д.).
Режим повторной загрузки: переключатель «Добавить недостающие / Заменить все» рядом с кнопками ③ и ④ на вкладке «Спецификации».
Галочка «Включить элементы из связей» снимается.
Поле «Связанный файл» убирается.
В отчёт попадают параметры, которых нет в модели.

Перед первым запуском
---------------------
1. Revit того года, что у моделей (в имени _R24 — это 2024).
2. Revit Batch Processor. При первом открытии Revit через RBP нажмите «Всегда загружать» для надстройки BatchRvt.
3. Файл со спецификациями — rvt только с пакетом стадии П (префикс «П», 8 пробелов).
   Собрать из полного РД-пакета один раз (уже сделано для PROJ: …_PROJ.rvt на шаре):
   Разовая подготовка РД→П (уже сделано для PROJ): в репозитории project\PROJ\разовое_источник_рд\
   (prepare_p_source.py, rename_rd_to_p.py, списки RBP). Пошагово — разовое_источник_из_рд.txt там же.
   В каталоге должны быть все хвосты из [сводная]; иначе вставка пишет «нет в файле со спецификациями».
   Не запускайте по rvt-источнику же список моделей ИОС.
4. Модели ИОС лучше никому не держать открытыми: занятый вид попадёт в лист «Пропуски».

Вкладка «Спецификации» (распределение, настройка проекта)
----------------------------------------------------------
Какие спецификации общего файла в какие модели и разделы — задаётся на вкладке «Спецификации», без правки кода и текстовых списков.
Эта настройка — единственный источник наборов: вставка в сводную и разделы, режим «Выборочно», проверка по эталону.

Сверху вниз:
1. «Общий файл» [Обзор…] — файл Revit со всеми спецификациями (можно путь RSN://).
2. «Модели» [Обзор…] [С сервера…] — папка с моделями (окно с адресной строкой, подходят и серверные пути; принимается только папка) или модели с Revit Server (в поле видна папка RSN://, выбор сохраняется).
   Берутся только инженерные модели: в имени файла есть код раздела в виде «_КОД_» (без учёта регистра): ОВ/OV, ПД/PD, ВК/VK, ПТ/PT, ОТ/OT, ХС/HS, ИТП/ITP, ЭОМ/EOM, СС/SS. Признаки IOS/ИОС/ВИС не используются. Сводная и общий файл исключаются, модели без кода нигде не показываются.
3. «Сводная модель» [Обзор…] [С сервера…] — модель SVOD/СВОД (можно путь RSN://).
4. «Стадия» (П, РД …). В именах спецификаций префикс стадии общего файла (например РД) заменяется выбранной стадией: имя вида в Revit = стадия + 8 пробелов + название. В значениях фильтров {СТАДИЯ} подставляется при вставке. Шифра в настройке нет.
5. [Скрыть неучаствующие] [Выделить всё] [Снять всё] и таблица распределения (ниже).
6. Кнопки слева направо: «Загрузить спецификации и модели», «Распределить», «В сводную», «В разделы» (рядом выпадающий список «Добавить недостающие / Заменить все») и отдельно «Посчитать элементы». «Распределить» и «Посчитать элементы» активны после загрузки. «В сводную» и «В разделы» активны после распределения и не зависят друг от друга: путь сводной модели и то, выполнялась ли уже «В сводную», кнопку «В разделы» не выключают. Во время работы Revit все кнопки серые.
   Загрузить спецификации и модели — спецификации и их КАТЕГОРИИ читаются из общего файла (Revit Batch Processor, один раз; категории сохраняются в настройке проекта), модели берутся по полю «Модели». Загрузка сбрасывает запомненный статус «В сводную». Если распределение уже есть, «В разделы» можно нажать сразу, без повторной «В сводную».
   Распределить — Revit не запускается, модели не открываются. Галочка модели = спецификация отмечена «В проекте» И её номер или категория входит в раздел модели по справочнику разделов (ниже). Раздел модели — по имени файла (_OV_, _ВК_ …). Пустая модель получает спецификации своего раздела так же. Ручные правки ячеек сохраняются, число элементов не стирается.
   В сводную — вставка в сводную модель спецификаций, отмеченных и в «В проекте», и в «Сводная»: со своим фильтром и с учётом связанных моделей.
   В разделы — вставка в модели разделов по распределению (то, что отмечено в таблице у каждой модели). Перед запуском «В сводную» и «В разделы» окно записывает готовый план вставки (отчеты\служебные\<время>\plan.txt): Revit берёт набор каждой модели из него. Файл служебный, править не нужно.
   Посчитать элементы — прежняя пробная вставка: на каждую модель одно открытие, все спецификации «В проекте» одной пачкой во временном виде, считаются элементы, транзакция откатывается — модель не сохраняется. Результат — числа в ячейках для информации, галочки не меняются. Время открытия, вставки, подсчёта и общее время — в отчеты\служебные\<время>\распределение.log.
   Режим «Добавить недостающие / Заменить все» один для «В сводную» и «В разделы»: «Добавить недостающие» — ничего не удаляется, вставляются только спецификации, которых ещё нет в модели (по номеру); «Заменить все» — спецификации списка в модели удаляются и вставляются заново из общего файла (если вид стоял на листе, пропадёт и он).
7. Внизу окна — строка статуса и [Открыть отчёт].
Ручная правка ячеек таблицы — любая, до ②, после ② и перед ④.
Выбор «В проекте»: галочки хранятся только в настройке проекта — раздел [inproject] файла отчеты\проект\распределение_<проект>.txt (его же читают «В сводную» и «В разделы»). Пишутся вместе с настройкой по «Сохранить» / «Сохранить как новый проект»; «Не сохранять» и «Отменить» возвращают прежние. «Загрузить спецификации и модели» подставляет галочки из [inproject] и пишет в статус «Выбор восстановлен из настройки проекта: N спек»; имена, которых нет в общем файле, перечисляются в статусе («нет в общем файле: …») и остаются в [inproject]. Раздела [inproject] нет — подсказка «Выбор не найден. Отметьте спеки или нажмите «Взять выбор из сводной»». Если снять все галочки «В проекте» и нажать «Сохранить», в файле остаётся пустой раздел [inproject] с пометкой «# пусто…»: при следующем открытии ничего не отмечено, и «В сводную»/«В разделы» тоже ничего не вставят (раньше окно в этом случае снова показывало отмеченными все).
Прежний отдельный файл выбора отчеты\проект\выбор_<проект>.txt больше не пишется. При первом открытии окна после обновления он переносится один раз: сначала делается резервная копия всей папки отчеты\проект\ и файлов истории/журнала (отчеты\проект\_backup_<гггг-ММ-дд_чч-мм>\, автоочистка её не трогает); если [inproject] пуст или его нет — галочки берутся из файла выбора (в статусе одна строка «Выбор «В проекте» проекта … перенесён в настройку проекта»); если и там, и там есть галочки и они различаются — остаётся [inproject] (его и читали скрипты Revit), разница записывается в _backup_<время>\перенос_выбора.txt. Сам файл выбора не удаляется, а переименовывается в выбор_<проект>.migrated_<гггг-ММ-дд>.txt. Повторный запуск ничего не делает. Откат: вернуть распределение_<проект>.txt из _backup_<время>\ и переименовать .migrated обратно в выбор_<проект>.txt.
«Взять выбор из сводной» (рядом с «Выделить всё»/«Снять всё»): разово читает имена спецификаций сводной модели (Revit) и ставит по ним «В проекте» (в памяти: в [inproject] попадёт по «Сохранить»). Если галочки уже есть, сначала спрашивает «Заменить текущий выбор выбором из сводной?» (по умолчанию «Нет»). Итог в статусе: «Отмечено по сводной: N; в сводной есть, но нет в общем файле: M». Список спецификаций таблицы остаётся из общего файла.
Столбец «В проекте»: галочка на группе отмечает, участвует ли группа в проекте (отмечает BIM-менеджер по BEP, включая сводную). Галочки есть и у отдельных спецификаций внутри группы (у группы — промежуточное состояние ◪). Столбец «Сводная» — какие из них идут в сводную модель.

Таблица: строки — группы. Имя группы = имя спецификации без хвоста и без префикса стадии: «7.1_Диаметр_Воздуховоды» и «7.1_Диаметр_Детали возд-в» — две группы, «5.3_Ширина_Отопит приборы» — отдельная. Хвосты: «Все», «Без значения», «Пустые», «999», «Уникальные_…»; внутри раскрытой группы показаны только они, спецификация без хвоста подписана «(основная)». Группа из одной спецификации — обычная строка без значка. Группа из нескольких раскрывается тонким значком слева от названия (как в дереве проводника) или двойным щелчком по названию. Столбцы — разделы (щелчок по заголовку раскрывает раздел до моделей; заголовок раздела цветной, его модели светлее того же цвета); сетка тонкая, одного цвета. Щелчок по ячейке ставит/снимает галочку у всей группы/раздела, ◪ — отмечено частично. Цвета ячеек: зелёный — отмечено по справочнику, жёлтый — ручная правка. Оранжевое название группы/спецификации — у неё нет категории в общем файле (и номера нет в справочнике) либо её категория не входит ни в один раздел справочника: такая спецификация не отмечается молча (подсказка на ячейке). Оранжевый заголовок раздела — раздела модели нет в справочнике. Правый щелчок по названию спецификации — перенести в другую группу.

Справочник разделов: текстовый файл отчеты\проект\справочник_разделов.txt, один на все проекты (рядом с настройками проектов, создаётся сам при первом запуске, в окне его нет). Блок [РАЗДЕЛ] (ОВ, ПД, ВК, ПТ, ОТ, ХС, ИТП, ЭОМ, СС, АВТ, ХЦ) и строки: «номера = 0, 1, 16.0, 16.1-18.1» (ведущие номера спецификаций, диапазоны допускаются), «категории = Воздуховоды; Оборудование» (категории Revit из общего файла), «кроме = 15.1» (номера, которые в раздел не входят). По умолчанию: общие номера 0, 1, 16.0, 17.0, 16.1, 17.1, 18.1 во всех разделах; ОВ — воздуховоды и их детали + оборудование; ПД — воздуховоды и детали; ВК, ПТ — трубы и фитинги + оборудование; ОТ, ХС, ИТП — как ВК плюс 15.1; ЭОМ, СС — лотки и их детали + короба; АВТ — кабельные лотки и их соединительные детали; ХЦ — трубы, соединительные детали трубопроводов, арматура и оборудование. Блоки [АВТ] и [ХЦ] в уже существующий справочник дописываются один раз (остальной текст файла не меняется; удалённый вами блок обратно не возвращается). Раздел модели — по коду «_КОД_» в имени (SITE_ORG_AVT_K1_R22, SITE_ORG_AVT_PRK_R22, SITE_ORG_HC_K1_R22), если кода нет — по имени папки модели (АВТ, ХЦ, AVT, HC; папка RVT пропускается). Неизвестный код раздела — отдельная колонка «Неизв.» в «Распределении» без автоматических галочек, в статусе перечислены такие модели. В таблице показаны только разделы, которые есть у проекта. Ошибка в файле (неизвестный раздел или ключ, не номер, нет «=», раздел дважды) — сообщение с номером строки при нажатии «Распределить», ничего не меняется. Исправьте файл и нажмите «Распределить» ещё раз.

Настройка сохраняется сама при любом изменении, отдельной кнопки нет: файл отчеты\проект\распределение_<префикс>.txt, где префикс — часть имени моделей до первого «_» (например распределение_PROJ.txt). Это рядом с отчётами проекта, не в папке кода. Один набор файлов инструмента подходит разным заказчикам: у каждого проекта свой файл.
Прежние schedule_sets.txt и список_спецификаций.txt больше не читаются и в папке не хранятся: таблица пуста, пока не нажата «Загрузить спецификации и модели».

Окно
----
Проекты. Вверху окна — список «Проект» (файлы отчеты\проект\распределение_<проект>.txt) и кнопка «Новый проект» (имя — обычно префикс моделей, например PROJ). Смена проекта подставляет всё сразу: общий файл, папку моделей (в т. ч. RSN://), стадию, сводную, ссылку на Google-таблицу, подключение Google (своё google_<проект>.cfg), «В сводную выполнена», режим вставки, отметки «Выборочно», выбор «В проекте», таблицу. У каждого проекта своя история (история_<проект>.txt) и свой журнал (задание_журнал_<проект>.txt) в отчеты\история. Всё это хранится в настройке проекта (и в файле google_<проект>.cfg рядом), а в ui_settings.txt остаются только последний открытый проект и общие параметры окна (интервал «Динамики», «Одна сборка в день», срок хранения служебных папок). Без проекта кнопки шагов неактивны. Старые значения из ui_settings.txt при первом запуске переносятся в проект, к которому они относятся (по префиксу моделей сводной), ничего не теряется: исходный файл сохраняется как ui_settings.до_проектов.txt; прежний общий задание_журнал.txt переносится в проект PROJ. Перед «В сводную», «В разделы» и «Собрать задание» в статусе указаны проект и таблица Google (конец адреса), куда пойдёт результат.
При открытии окна на вкладке «Спецификации» сразу показывается таблица из сохранённого кэша спецификаций проекта (без Revit, с отметками и распределением как сохранено): берётся сохранённая настройка проекта, а если её нет — самая свежая настройка с тем же общим файлом. Нет кэша — пустая таблица с шапкой и серыми строками и подсказкой «Укажите общий файл и нажмите „Загрузить спецификации и модели“».
Таблица занимает всё место окна, кнопки внизу. «Группа / спецификация» и «В проекте» — фиксированной ширины, «Сводная» и столбцы разделов делят остаток поровну; в узком окне (минимум 960×640) появляется горизонтальная прокрутка, столбцы не сжимаются.
Две вкладки: «Спецификации» (всё до вставки в модели — см. выше) и «Задание».
Все пути (общий файл, модели, сводная, RSN://), стадия и настройка проекта сохраняются сами при любом изменении; отдельной кнопки сохранения нет. Вкладка «Задание» берёт сводную и настройку со вкладки «Спецификации» и повторно их не спрашивает.
Прежние настройки подхватываются: пути общего файла и сводной, стадия, папка моделей, режим вставки. Если «Модели» пусто, а был список моделей разделов (шаг «Разделы» прежних версий), его общая папка (или RSN://) становится полем «Модели»; сам список-файл не изменяется. Прежние режимы вставки «сводная» и «разделы» объединены в один переключатель: «Заменить все» остаётся, только если он стоял у обоих; «Первичная загрузка» читается как «Добавить недостающие» (в модели без пакета это то же самое).
Итог ③ и ④ — «готова» или «Не готово: с ошибкой N из M моделей»; до запуска проверяется версия Revit: модели одной версии, общий файл не новее моделей, иначе запуск останавливается.
«Заменить все» запускается только после подтверждения: окно пишет число моделей и спецификаций списка, которые будут удалены и вставлены заново (по умолчанию «Нет»).
Отчёт прогона (xlsx: Сводка, Вставлено, Параметры, Пропуски) после «В сводную» и «В разделы» пишется напрямую (Open XML: zip + XML средствами .NET), Excel и COM для него не запускаются и не нужны, временных книг нет. Не удалось записать xlsx — в статусе причина и ссылка «Открыть CSV» (сводка прогона показывается в проводнике). Excel (COM) остаётся только для чтения xlsx для Google при отсутствии готового payload (push_google.ps1); там закрывается только свой процесс Excel (PID из запуска / по hwnd своего COM-объекта), при неизвестном PID — ничего.
Пока идёт Revit, кнопки и вкладки серые. Окно не закрывать: Revit откроется поверх. Когда шаг закончен, окно выходит вперёд и пишет итог. Внизу строка хода: номер модели, имя файла, сколько вставлено, сколько пропущено.
Файлы «Выборочно» в отчеты\история: на проект один файл история_<проект>_состояние.txt (буфер замечаний, даты проверок, каталог последней выгрузки). Раньше их было три (история_<проект>_буфер.txt, _проверки.txt, _каталог.txt): при первом открытии окна после обновления они объединяются автоматически, перед этим делается резервная копия отчеты\проект\_backup_<время>, а прежние файлы переименовываются в …migrated_<дата>.txt (не удаляются, их можно убрать вручную, когда всё проверено). История и журнал не меняются.

Задание — кнопка «Собрать задание». Выгрузка из сводной через Revit, затем файл отчёта xlsx в папке проекта отчеты\<проект>\ (например отчеты\PROJ\2026-10-05_12-30-00_PROJ.xlsx; без проекта — прямо в отчеты\) — вариант 1 со сводкой и листами разделов. Excel для этого шага не нужен (Open XML, lib\DocumentFormat.OpenXml.dll). JSON для Google (google_push_payload.json), фильтры_спецификаций.txt и итог выгрузки export.txt (раньше три файла manifest.txt, export_result.txt, catalog.txt; папки прежних прогонов читаются как раньше) пишутся один раз в служебную папку прогона отчеты\служебные\<время>\ (её чистит окно через 30 дней). Рядом с xlsx в папке проекта этих копий больше нет; по JSON после сборки обновляется онлайн-таблица Google (если настроен служебное\google_push).
Пояснения к полям — во всплывающих подсказках (наведите мышь). Подробности — в этой инструкции.
Задание, режим «Выборочно»: слева галочка модели или раздела — «выгружать эту модель» (при отметке все её спецификации отмечаются). Щелчок по модели или разделу показывает справа его спецификации (по распределению проекта): у модели — её, у раздела — объединение по моделям раздела. Галочки спецификаций хранятся для каждой модели отдельно; галочка у раздела ставит/снимает спецификацию у всех его моделей, «[частично]» — отмечена не везде. «все»/«ничего» действуют только на выбранный узел. Выгружаются отмеченные пары «модель × спецификация» (итог — «Всего к выгрузке»); остальные пары остаются в отчёте с прошлыми данными серым, их замечания не закрываются. Списки берутся из прошлых сборок: чтобы они обновились (новая модель или спецификация), соберите задание в режиме «Всё».
Сводную и разделы повторяют, только если сменился список. Задание собирают снова после правок в моделях.
Кнопка «Классификатор» (вкладка «Спецификации»): путь к файлу классификатора берётся из настройки проекта — строка classifier=<UNC-путь> в разделе [project] файла отчеты\проект\распределение_<проект>.txt. Строки нет — для PROJ используется официальный путь \\server\share\BIM\classifier.txt, для другого проекта окно попросит вписать строку. Путь уходит скрипту set_assembly_code.py через run.cfg; набор моделей и проверки (UNC, файл читается, только модели с префиксом проекта) прежние.
Ссылка на Google-таблицу на вкладке «Задание» — для чата проектировщикам. Если в папке служебное\google_push настроен google_push.cfg (см. README), после успешной сборки задания таблица обновляется сама: листы «Сводка» и разделы. «Динамика» в Google не уходит.
Адрес Google — на проект. На вкладке «Задание» полей адреса и секрета нет: подключение читается молча из отчеты\проект\google_<проект>.cfg (рядом с распределение_<проект>.txt; в git не попадает, секрет нигде не показывается и в логи не пишется), в окне — строка «Google: проект X, адрес …конец». Кнопка «Подключить Google…» (если файла нет) или «Изменить подключение…» открывает маленький диалог: адрес (…/exec) и секрет (маскированное поле; при изменении пустой секрет оставляет прежний); существующие cfg сами не переписываются. «Проверить» — формат (как в проверить_google.ps1), ping и пробный POST. Каждый проект пишет только в свою таблицу. Перед отправкой в статусе и в журнале (отчеты\логи\google_push.log) указано, куда уходит отправка: проект и конец адреса. Общий служебное\google_push\google_push.cfg — только запасной вариант (окно его только читает: не создаёт, не переписывает и не удаляет; если им пришлось воспользоваться, в google_push.log пишется предупреждение): если у проекта своего адреса нет, окно спрашивает «У проекта нет своего адреса Google. Отправить в общую таблицу из google_push.cfg?» (по умолчанию «Нет»); без подтверждения в общую таблицу ничего не уходит.
«С сервера…» берёт модели (и сводную) с Revit Server. Список папок читается по HTTP. В поле попадает путь RSN://, не адрес HTTP. Скрипт списка лежит в папке «служебное» этого окна. Перед запуском по пути RSN:// ставится правка Revit Batch Processor из той же папки «служебное». Без правки программа пишет «File exists: NO».
Окно растягивается: таблица растёт, кнопки остаются у нижнего края.

Что происходит с моделью
------------------------
Имена берутся из файла со спецификациями как есть: «П», восемь пробелов, затем номер.
Папка «П» в диспетчере получается из этих пробелов. Верхняя папка — ADSK_Назначение вида = _Проверка проекта.
Режим вставки — один переключатель на вкладке «Спецификации», для ③ и ④:

  Добавить недостающие — ничего не удаляется; вставляются только спецификации списка,
  которых ещё нет в модели (по номеру спецификации). Спецификация, которая уже есть под другим
  написанием («Cантехприборы» с латинской C), считается той же самой и не дублируется.

  По умолчанию — «Добавить недостающие». Модель, в которой спецификаций списка ещё нет, получает первичную загрузку (ничего не удаляется) независимо от выбранного режима; в отчёте, лист «Сводка», колонка «Режим»: «первичная (автоматически)», «добавление», «замена».

  Заменить все — удалить в модели спецификации из текущего списка (по номеру спецификации),
  вставить список заново из файла-источника.

Если при замене спецификация стояла на листе, вместе с удалением пропадает и вид на листе.

Отчёт вставки
--------------
Один файл xlsx в папке «отчеты» рядом с этим файлом. Его пишет загрузка в сводную и в разделы.
Имя: 2026-09-22.xlsx. Повтор в тот же день — 2026-09-22_2.xlsx.
Листы: «Сводка», «Вставлено», «Параметры», «Пропуски».
«Вставлено» — строка на модель. Кнопка «+» слева раскрывает имена спецификаций. Путь модели в таблице не повторяется, только имя файла.
В сводке колонки «Удалено» и «Вставлено» — это то, что реально произошло в модели.

Задание
-------
Каждый запуск пишет новый файл в папке «отчеты». Имя — дата, время и код проекта из сводной, например 2026-09-30_08-00-00_PROJ.xlsx. Старые файлы не затираются.
Список «Спецификации (по номерам)» на вкладке «Выборочно» показывает спецификации выделенного узла дерева «Модели (по разделам)»; узел выделяется при любом щелчке (в том числе по галочке), после обновления дерева выделение восстанавливается (иначе выбирается первый раздел). «Открыть отчёт» без последнего файла открывает отчеты\<текущий проект>\, если такая папка есть, иначе отчеты\. Файлы в корне отчеты\ не переносятся; история\ остаётся общей (история_<проект>.txt).

Журнал для «Динамики» — файл история_PROJ.txt (код из имени сводной) в папке «отчеты\история» (при первом запуске после обновления старые файлы переносятся туда сами; файлы прогона — в «отчеты\служебные», старше 30 дней удаляются). После каждой успешной сборки дописывается срез по модели, спецификации и параметру. Повтор в тот же день заменяет сегодняшние строки.
На вкладке «Задание» выбирается интервал (7 / 14 / 30 дней или свои даты). Лист «Динамика» в том же файле — отработанные замечания за период, группировка как на листах разделов. Кнопка «Собрать динамику» пересчитывает только этот лист из истории, без Revit.
Лист раздела: строка модели, под ней спецификация, под ней элементы. Сразу видно модель и спецификацию. Элементы скрыты: нажми 3, потом 2. Подсказка жёлтая.
В колонке «Спецификация» имя целиком, как в Revit. В выгрузку попадают спецификации с «Пустые» или «Без значения» в имени и четыре проверки без такого суффикса (каждая строка — замечание): «0_Ошибка типоразмера» (Параметр ADSK_Наименование), «1_Классификатор_999» (Код по классификатору), «16.0_Корпус_Кириллица» (ADSK_Номер здания), «17.0_Секция_Кириллица» (ADSK_Номер секции). В «Значении» — текст этой колонки. Порядок на листах разделов и в Сводке — по номеру: 0 первая, «1_Классификатор_999» сразу после «1_Классификатор_Пустые», 16.0/17.0 раньше 16.1/17.1. Номера 0, 1, 16.0 и 17.0 есть в общих номерах справочника, поэтому эти спецификации входят в каждый раздел и в «Выборочно» отмечаются у моделей всех разделов. Обзорные «Все» и «Уникальные» в отчёт не выгружаются. Пустая спецификация пишется в итог выгрузки (служебный export.txt, раздел [manifest]) строкой «*empty*»: это проверено и замечаний нет, а не «не выгружали». Вкладка листа — короткое имя раздела, туда полное имя не влезает.
Сводка: модели против спецификаций. Колонки — только спецификации, где есть замечания сейчас или были в прошлой выгрузке (без «пустых» нулевых колонок). Число — сколько элементов не заполнено. Оранжевый — есть замечания, зелёный ноль — чисто, синий ноль — в прошлой выгрузке были, сейчас нет. В скобках прошлое число: 3 (5).
Три колонки дат на «Сводке» — три последних дня выгрузки.
Скрипт из статьи про Google Sheets это не заменяет. Там кнопка копирует строки внутри уже открытой таблицы. Из Revit в Google файл сам не уходит.

Разделы
-------
ОВ — воздуховоды, оборудование, география.
ПД — воздуховоды.
ВК, ПТ — трубы, оборудование, география.
ОТ, ХС (файл _HS_), ИТП — то же плюс мощность тепловая.
ЭОМ, СС — лотки; короба Revit (трубы под кабель, MR 7.9.1: диаметр/длина на этапе 2–3 П); география щитов. Имя системы оборудования туда не копируется.
Спецификации по сантехприборам (2.5, 4.5, 16.2–18.2) в списки и вставку не входят — в зоне ответственности ИОС их нет.
