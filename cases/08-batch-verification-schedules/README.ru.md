# Кейс 08 — Проверочные спецификации

[← К хабу](../../README.ru.md) · [EN](README.md)

## Проблема

В модели раздела должны стоять те же проверочные спецификации, что в шаблоне проекта: пустые значения, коды классификатора, имена систем и остальные проверки, которые BIM-менеджер отметил для проекта. Ручное копирование и сбор результата в одну книгу не масштабируются на список моделей. Книгу нужно собрать без установленного Excel, а те же таблицы иногда нужно отправить в Google Таблицы.

## Решение

Окно оператора (`Проверочные спецификации.vbs`) собирает прогон. Код лежит в `служебное/`. Окно:

- читает модель-шаблон и распределение проекта (какие спецификации к какому разделу)
- выгружает данные спецификаций скриптом [`служебное/скрипты/export_schedules.py`](src/служебное/скрипты/export_schedules.py) (только чтение)
- пишет `.xlsx` через [DocumentFormat.OpenXml](src/служебное/lib/LICENSE-MIT.txt) — Excel не нужен
- может отправить те же таблицы в Google Таблицу через [`служебное/google_push/`](src/служебное/google_push/) (Apps Script `Code.gs` и `push_google.ps1`)
- может вставить спецификации шаблона в хост ([`insert_schedules.py`](src/служебное/скрипты/insert_schedules.py)) и проставить коды классификатора ([`set_assembly_code.py`](src/служебное/скрипты/set_assembly_code.py))

Коды разделов (ОВ, ВК, ЭОМ, …) — в [`служебное/скрипты/разделы.txt`](src/служебное/скрипты/разделы.txt). Имя проекта, префикс моделей, адрес таблицы и путь классификатора задаются в окне. В этом репозитории пример проекта — `PROJ`, путь классификатора — `\\server\share\BIM\classifier.txt`.

## Входы и выходы

| | |
|--|--|
| Входы | Шаблон `.rvt`, список моделей (диск, UNC или `RSN://`), `servers.cfg`, по желанию `служебное/google_push/google_push.cfg` из образца |
| Выходы | Книга `.xlsx`, текстовые журналы в `отчеты/` (папка создаётся при работе и в git не входит), по желанию обновление Google Таблицы |
| Пишет в модель? | **Выгрузка: нет.** Вставка спецификаций и проход классификатора **да** (транзакции; совместная модель синхронизируется) |

## Масштаб / контекст проекта

| | |
|--|--|
| Статус | Проверено на рабочих моделях |
| Эффект | Одно окно на шаблон, список моделей, xlsx и необязательную Google Таблицу |
| Excel | Для сборки книги не нужен |
| Google Таблицы | По желанию. URL веб-приложения и секрет в этот репозиторий не входят |

## Безопасность

- Вставку и проход классификатора сначала гоняйте на копии. Вставка удаляет и заново создаёт проверочные спецификации, затем синхронизирует совместную модель.
- Выгрузка не вызывает Save, Sync и Relinquish.
- В `google_push.cfg` лежат URL и общий секрет. Опубликован только `google_push.cfg.example`, оба поля пустые. В `Code.gs` стоит `PUSH_SECRET = 'REPLACE_ME_WITH_LONG_RANDOM_SECRET'`.
- Не кладите в это публичное дерево настоящий id таблицы, URL веб-приложения или секрет.
- Хосты Revit Server в `servers.cfg` — заглушки (`revit-server-20xx.example.local`).

Подробнее: [docs/SAFETY.ru.md](../../docs/SAFETY.ru.md)

## Запуск

1. Скопировать `src/` на Windows с нужным годом Revit и [Revit Batch Processor](https://github.com/bvn-architecture/RevitBatchProcessor). `служебное/разработка/` — тесты и заметки; окну она не нужна.
2. Прописать хосты в `servers.cfg`.
3. Для Google Таблиц скопируйте `служебное/google_push/google_push.cfg.example` в `google_push.cfg` на этом ПК и впишите URL и секрет. Разверните `Code.gs` как веб-приложение. Секрет в git не коммитьте.
4. Дважды щёлкните `Проверочные спецификации.vbs`. Лаунчер находит `ui_schedules.ps1` в служебной папке.
5. Выберите шаблон, модели и разделы. Выгрузка пишет книгу. Вставка и классификатор — отдельные действия.

`служебное/rbp_rsn_patch/apply_rsn_support.ps1` — тот же локальный патч RBP, что в кейсе 01: правит установленный RBP, чтобы пути `RSN://` проходили `File.Exists`. Исходников RBP в нём нет.

Инструкция оператора: [`src/ИНСТРУКЦИЯ.txt`](src/ИНСТРУКЦИЯ.txt)

## Тесты

[`src/служебное/разработка/tests/`](src/служебное/разработка/tests/) — автотесты на Python: цепочка, раскладка xlsx, коды разделов, полезная нагрузка Google и логика окна. Многие пропускаются, если в `PATH` нет `pwsh`. Revit не нужен.

В опубликованных тестах нет выгрузок фильтров клиента и каталога шаблона клиента. Два теста пропускаются, если этих файлов нет. Группировка проверяется коротким синтетическим списком в `test_dist_groups.py`. Каталог-заглушка на 30 строк: [`src/служебное/разработка/данные/samplesite_template_specs.tsv`](src/служебное/разработка/данные/samplesite_template_specs.tsv).
