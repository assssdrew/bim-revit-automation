# Кейс 04 — оповещения об обновлении моделей на FTP (ntfy / Telegram)

[← К хабу](../../README.ru.md) · [EN](README.md)

## Проблема

Команда обменивается Revit-моделями (и смежными файлами) через общий FTP. BIM-менеджеру нужен **push на телефон**, когда появилась/изменилась папка или файл — без постоянного FileZilla. Мобильные FTP-клиенты это не умеют (у FTP нет push-событий; iOS почти не даёт фоновый опрос).

На рабочих ПК часто **закрыт исходящий HTTPS** к сервисам уведомлений (`ntfy.sh`, `api.telegram.org`), поэтому watcher нельзя держать на «заблокированной» офисной машине.

## Решение

PowerShell-набор:

1. Опрашивает одну или несколько FTP-папок (обычный FTP или опционально TLS)
2. Сравнивает имена / размеры / время FTP с локальным `state.json`
3. Шлёт push через **ntfy** (по умолчанию) или **Telegram**
4. Крутится по расписанию Windows на ПК, у которого есть и FTP, и доступ к API уведомлений (например домашний всегда включённый)

В комплекте: хранение пароля (`Export-Clixml`), тесты связи, несколько путей, строки NEW/UPD/DEL с **временем FTP** и временем проверки.

## Эффект

| | |
|--|--|
| Статус | **В проде** (проверено на реальном обмене) |
| Пишет модели? | **Нет** — только LIST FTP |
| Масштаб | Несколько `RemotePaths`, глубина обхода настраивается |

## Безопасность

- Не загружает / не удаляет / не переименовывает на FTP
- Не коммитить `config.json`, `credentials.xml`, `state.json`
- Topic ntfy — секрет; токен Telegram при утечке — revoke у BotFather
- Для watcher лучше отдельный FTP-логин **только на чтение**

## Запуск

1. Скопировать [`src/`](src/) на ПК с интернетом и доступом к FTP
2. `config.example.json` → `config.json`
3. Телефон: **ntfy** + свой topic (или бот Telegram)
4. `Save-FtpCredentials.ps1`
5. `Test-Ntfy.ps1` (или `Test-Telegram.ps1`)
6. `Watch-FtpModels.ps1` — baseline без спама
7. Изменение на FTP → повторный запуск → уведомление
8. `Register-ScheduledTask.ps1` — каждые 5 минут
