# Кейс 06 — Операции с моделями (имена, апгрейд, связи, рабочие наборы) (v3.1.0)

[← К хабу](../../README.ru.md) · [EN](README.md)

## Проблема

Парк разделов (~50+ workshared-моделей) нужно сдвинуть вместе: новые имена, иногда папка или год Revit, затем все **RVT Links** должны смотреть на новые файлы. Ручной Save As / Detach / Load From ломает цепочку, если хост сохранить раньше, чем появятся связи. Новые модели ещё нужно положить на правильные рабочие наборы.

## Решение

Каркас **v3.1.0**. Одно окно (`Операции с моделями.vbs`) открывает `служебное/presets.ps1`. Скрипт подключает `start_ops.ps1` и `job_lib.ps1` из той же папки `служебное`. `start_ops.ps1` находит Revit Batch Processor и запускает каждый проход. [Revit Batch Processor](https://github.com/bvn-architecture/RevitBatchProcessor) — только хост батча.

Лаунчер лежит в `src/`. Весь код — в `src/служебное/`. Рабочие файлы (`rvt_list.txt`, `job_paths.csv`, `mapping.csv`, …) появляются рядом с лаунчером и в git не входят.

Вкладки: переименование / перенос, перепривязка связей, смена года, **добавить связи** и **рабочие наборы**. «Пробный прогон» показывает план и не открывает Revit. Проход 1 — `saveas_central.py` (**v3.1.0**, Create New Local, Detach выкл). Старый год Revit Server сначала снимается в локальный буфер (`detach_to_buffer.py`, Detach вкл, только этот ПК). Проход 2 — `update_rvt_links.py`. Рабочие наборы — отдельная пара: `read_worksets.py`, затем `apply_workset_links.py`.

`saveas_central.py` пишет `SCRIPT_VERSION` 3.1.0. `detach_to_buffer.py` и `update_rvt_links.py` по-прежнему 3.0.0. `read_worksets.py` — 1.0.1, `apply_workset_links.py` — 1.1.3.

Старое меню `служебное/run_cascade.cmd` остаётся.

UNC→UNC с апгрейдом года буфер не нужен: новая Revit открывает старый файл на шаре и сразу Save As.

## Масштаб / контекст проекта

| | |
|--|--|
| Статус | Проверено на рабочих моделях |
| Эффект | В среднем примерно в 4–5 раз быстрее, чем вручную; поэтапные Save As, перенос, relink и рабочие наборы из одного задания |
| Масштаб | Парк разделов, UNC / `RSN://` |
| UX | Одно окно. Старое меню: `служебное/run_cascade.cmd` |
| Пишет в модель? | **Да** — Save As хранилища, перепривязка связей, правка наборов |

## Безопасность

- Боевые хранилища назначения: Create New Local, Detach **выкл**
- Detach **вкл** только для **локального буфера**, когда уходим со старого Revit Server (не для боевой централи)
- Вложенные связи из хоста не переписываются — открывается каждая модель, которая владеет связью
- Старые файлы удаляются только после зелёного прохода 2
- Вставка связи идёт по общим координатам. Связь с несогласованными координатами пропускается
- Операции имён выполняются только если токен есть в имени

Подробнее: [docs/SAFETY.ru.md](../../docs/SAFETY.ru.md)

## Запуск

1. Скопировать `src/` на ПК с нужными годами Revit и RBP. Папка `служебное` должна лежать рядом с лаунчером.
2. Прописать хосты в `servers.cfg` (в этом репо — заглушки)
3. Дважды щёлкнуть `Операции с моделями.vbs`. Лаунчер сам находит `presets.ps1` в подпапке. Окно не стартует без `start_ops.ps1` и `job_lib.ps1` рядом с `presets.ps1`.
4. Выбрать модели, задать правила, сделать пробный прогон, затем запустить вкладку.
5. Старое меню в `служебное`: `run_cascade.cmd`.
