# Кейс 06 — Операции с моделями (имена, апгрейд, связи)

[← К хабу](../../README.ru.md) · [EN](README.md)

## Проблема

Парк разделов (~50+ workshared-моделей) нужно сдвинуть вместе: новые имена, иногда папка или год Revit, затем все **RVT Links** должны смотреть на новые файлы. Ручной Save As / Detach / Load From ломает цепочку, если хост сохранить раньше, чем появятся связи.

## Решение

Одно окно (`Операции с моделями.vbs`, или `show_ops.vbs` с латинским именем файла) открывает `presets.ps1`. Скрипт **зависит от `start_ops.ps1` и `job_lib.ps1`**: подключает оба через точку и требует, чтобы они лежали в той же папке. `start_ops.ps1` находит Revit Batch Processor и запускает каждый проход. [Revit Batch Processor](https://github.com/bvn-architecture/RevitBatchProcessor) — только хост батча.

В списке: модель / состояние / откуда / путь. Колонка «Станет» есть только при переименовании, «Старый/Новый путь» — только при переносе. **Подробности** задаёт правила имён. **Запустить** сохраняет задание и гоняет проходы (буфер / Save As / перенос файлов / связи / удаление старых). Перед перезаписью спрашивает, все ли вышли из моделей.

Старое меню `run_cascade.cmd` в папке остаётся.

1. Выбор моделей (шара / файлы / `RSN://`)
2. Операции имён по образцу (`delete` / `replace` / `insert`) + куда / год
3. **Save job** пишет `mapping.csv`, `job_paths.csv`, списки — **до** открытия Revit
4. Конвейер:
   - **Pass 1** `saveas_central.py` — новые хранилища (Create New Local, Detach **OFF**)
   - Если источник — старый год Revit Server: сначала `detach_to_buffer.py` (**Detach ON**, буфер только на этом ПК, не боевая централь)
   - **Pass 2** `update_rvt_links.py` — перенацелить связи по `job_paths.csv`
5. После зелёного Pass 2: удалить старые UNC / список старых RSN для Admin

UNC→UNC с апгрейдом года буфер не нужен: новая Revit открывает старый файл на шаре и сразу Save As.

## Масштаб / контекст проекта

| | |
|--|--|
| Статус | Проверено на рабочих моделях |
| Эффект | В среднем примерно в 4–5 раз быстрее, чем вручную; поэтапные Save As, перенос и relink из одного задания |
| Масштаб | Парк разделов, смесь UNC / `RSN://` |
| UX | Одно окно: список, колонки переименования/переноса по необходимости, Подробности, Запустить. Старое меню: `run_cascade.cmd` |
| Пишет в модель? | **Да** — Save As хранилища, затем remap связей |

## Безопасность

- Боевые целевые хранилища: Create New Local, Detach **OFF**
- Detach **ON** только для **локального буфера** при уходе со старого Revit Server
- Вложенные связи из хоста не правятся — открывается каждая модель, которая сама держит связь
- Удаление старых файлов только после зелёного Pass 2
- Операция имени срабатывает, только если токен есть в имени (исключения для одного конкретного токена — отдельная замена)

Подробнее: [docs/SAFETY.ru.md](../../docs/SAFETY.ru.md)

## Запуск

1. Скопировать `src/` на ПК с нужными годами Revit и RBP
2. Прописать хосты в `servers.cfg` (в этом репо — заглушки)
3. Дважды щёлкнуть `Операции с моделями.vbs`. `show_ops.vbs` открывает то же окно. Без `start_ops.ps1` и `job_lib.ps1` рядом `presets.ps1` не запустится.
4. Выбрать модели, задать правила имён, нажать «Запустить».
5. Старое меню в той же папке: `run_cascade.cmd` → **2** список → **1** преднастройки → Save job. *Save job* (`job_lib.ps1`) пишет `rbp_checklist.txt` рядом с `mapping.csv` (в репозитории файла нет): год Revit, Detach / Create New Local, task-скрипт и список, один прогон RBP на год. `run_cascade.cmd` выводит его на экран. По желанию: Windows Move UNC (**3**), затем удаление старых (**4**).
