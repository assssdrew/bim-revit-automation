# Batch: rename / move / upgrade Revit / relink RVT / delete old

Версия каркаса: **3.1.0**

Одно окно преднастроек + прогоны RBP (SaveAs, Detach на буфер ПК, LoadFrom, удаление). Заменяет прежние `batch_update_rvt_links` и `batch_relink_moved_paths`.

## Запуск (новое окно операций)

Двойной клик по **`Операции с моделями.vbs`** — открывается одно окно «Операции с моделями Revit» (`presets.ps1`). Лаунчер запускает PowerShell с окном 0, поэтому нет ни консоли, ни вкладки Windows Terminal; RBP и проходы PowerShell тоже стартуют без консоли (`Start-OpsHiddenProcess`). `.vbs` хранятся в CRLF.

- Выбор моделей встроен в окно: `choose_models.ps1` подключается как библиотека (консольное меню при этом не запускается).
- Из окна же запускаются прогоны Revit Batch Processor: `start_ops.ps1` ищет `BatchRvt.exe` и стартует нужный проход по чеклисту.
- Старый путь через `служебное\run_cascade.cmd` / `служебное\presets.cmd` остаётся рабочим.
- Весь код в `служебное\`, данные (`rvt_list.txt`, `job_paths.csv`, …) — в корне.
- `rvt_list.txt` создаётся при работе и в git не хранится (`.gitignore`).

## Структура папки

В корне только то, что нужно пользователю: ярлык, инструкция, `servers.cfg` и его рабочие данные. Весь код и тесты — в `служебное\`.

```
batch_model_ops\
  Операции с моделями.vbs   единственный ярлык (окно скрыто, без консоли)
  ИНСТРУКЦИЯ.txt            краткая инструкция
  README.md                 это описание
  servers.cfg               хосты Revit Server (читается из корня)
  .gitignore
  служебное\                код, .cmd, тесты
  (rvt_list.txt и др.)      рабочие данные, создаются при работе, в git не хранятся
```

| `служебное\` | Что |
|---|---|
| `presets.ps1`, `ui_logic.ps1`, `job_lib.ps1`, `start_ops.ps1` | окно и задания |
| `choose_models.ps1`, `make_rvt_list.ps1` | выбор моделей (окно подключает как библиотеку) |
| `delete_old_models.ps1`, `move_centrals.ps1`, `safety_lib.ps1` | проходы «уборка» и «перенос» |
| `*.py` | скрипты RBP (IronPython): `detach_to_buffer`, `saveas_central`, `update_rvt_links`, `ops_lib`, `relink_prefix` |
| `*.cmd` | ручные меню и обёртки (`run_cascade`, `presets`, `choose_models_path`, `move_centrals`, `delete_old_models`, `reset_report_session`, `patch_rbp_open_failures`); работают из корня (`pushd "%~dp0.."`) |
| `patch_rbp_open_failures.ps1`, `rbp_open_fail_patch\` | автономная копия патча RBP (основной — `tools\rbp_patches`) |
| `tests\` | автотесты |

**Код и данные.** В `.ps1` две переменные: `$CodeDir` — папка `служебное\` (скрипты, `.py` для RBP), `$ToolDir` — корень инструмента (данные). Ярлык `.vbs` находит `служебное\presets.ps1` перебором подпапок (в `.vbs` нет кириллицы: WSH читает его как ANSI) и ставит текущей папкой корень.

Данные остаются в корне, как раньше: `rvt_list.txt`, `rvt_list_new.txt`, `rvt_list_staging.txt`, `rvt_list_move.txt`, `mapping.csv`, `job_paths.csv`, `job.json`, `rbp_checklist.txt`, `relink_map.csv`, `to_delete_rsn.txt`, `models_path.cfg`, `last_selection.cfg`, `servers.cfg`. Отчёты — `batch_model_ops\отчёты` (папка создаётся при работе, в git не хранится; путь передаётся скриптам RBP как `reports_dir` в `job.json`).

- `job_lib.ps1` → `New-OpsPassQueue -ToolDir <корень> -CodeDir <служебное>`: `Task` (`.py`/`.ps1`) берётся из `служебное\`, `List` — из корня.
- `start_ops.ps1` передаёт `move_centrals.ps1` / `delete_old_models.ps1` явный `-ToolDir <корень>`; без него они сами берут папку на уровень выше своей.
- `.py` для RBP ищут `job_paths.csv` / `mapping.csv` сначала на уровень выше своей папки, потом в своей (старая раскладка) и в прежних запасных путях; `ops_lib.py` и `relink_prefix.py` подключаются из папки скрипта.
- `tests\paths.tests.ps1` проверяет раскладку: в корне только разрешённые файлы, ярлык ведёт к `служебное\presets.ps1`, все ссылки из `.vbs`/`.cmd`/`.ps1` ведут к существующим файлам.

## Что делает окно

Пять вкладок, у всех одна сетка:

- сверху панель: слева «Файлы…», «Папки…», «Revit Server…», «Взять с вкладки…», справа «Открыть список…», «Сохранить список…»;
- список моделей (`ListView`, последняя колонка занимает остаток ширины);
- под списком «Выделить все», «Снять», «Убрать» и счётчик «В списке: N · отмечено: M»;
- настройки вкладки: подписи слева в колонке 140 px, поля справа;
- внизу общая строка: состояние (ошибки — красным), «Пробный прогон» и кнопка запуска вкладки («Запустить», «Вставить связи» или «Записать наборы»).

Подсказок в самом окне нет, всё объяснено здесь. У каждой вкладки свой список моделей, прогон вкладки не трогает списки и настройки других вкладок. «Взять с вкладки…» копирует отмеченные модели другой вкладки.

**«Пробный прогон»** показывает план активной вкладки (что откроется, что во что сохранится, что будет вставлено, переименовано или удалено) и ничего не запускает и не пишет: ни `job.json`, ни списков, ни отчётов.

Окно открывается 1320×860, меньше 1180×760 не сжимается; при развороте на весь экран растут списки и колонки путей. Высота разделителей на вкладках 4 и 5 запоминается в `ui_layout.cfg` (в git не хранится).

`mapping.csv`, `job_paths.csv`, `rvt_list*.txt`, `job.json`, `rbp_checklist.txt` пишутся только при запуске (не при пробном прогоне).

### 1. «Перенос и переименование»

Колонки: «Модель», «Станет», «Старый путь», «Новый путь», «Состояние».

- **Имя: было → стало.** В «было» подставляется имя первой модели, в «стало» впишите, каким оно должно стать. Правило разбирается само через 0,4 с после ввода (`delete` / `replace` / `insert`; операция действует, только если токен есть в имени) и сразу видно в «Станет». Пустое «стало» — переименования нет. «Стало» без «было» или пример, который правило не воспроизводит, — красная строка состояния «Имя: …», запуск не пойдёт.
- **Папка: было → стало.** В «было» подставляется общая папка отмеченных моделей, «Обзор…» выбирает папку «стало». Пустое «стало» — переноса нет, модели сохраняются в своей папке. Если все пути начинаются с «было» (граница по папке), заменяется начало пути (другой сервер или корень шары), иначе — этот кусок внутри пути. Одинаковые «было» и «стало» — ошибка «совпадают».
- Подстановки не затирают введённое вручную.
- **Старые модели:** «оставить» (по умолчанию) или «удалить после прогона (перенос в _to_delete)»: старая модель переносится в `_to_delete`, только если отчёты подтверждают новую (см. «Безопасность»).
- **«Разрешить перезапись существующих файлов»** — по умолчанию выключено.
- Если сразу нечего делать (ни нового имени, ни новой папки, ни ручных правок), «Запустить» отвечает «Делать нечего…».

Если в окне что-то внутри сломалось, в строке состояния появляется «Внутренняя ошибка окна: …», подробности с местом в коде пишутся в `отчёты\_window_errors.log`.

### «Новый путь» всегда полный

Путь обязан быть полным и абсолютным (`D:\…`, `\\сервер\ресурс\…` или `RSN://…`), оканчиваться на `.rvt`, без пустых папок; при смене версии с Revit Server так же проверяется путь файла в буфере. Если путь получился относительным, пустым или без папки, у модели в «Состоянии» стоит красное «Ошибка пути», при наведении курсора видна причина, а «Запустить» показывает причины и **не запускает** прогон. Старый путь без папки (например, импортированный список) тоже ошибка.

### Таблица моделей

- Выделите строки и нажмите **Ctrl+C** (или «Копировать» в меню по правой кнопке): в буфер уходят «Старый путь» и «Новый путь» через табуляцию, одна модель на строку. Отдельно: «Копировать только старые пути» / «только новые пути». Над ячейками всплывает подсказка с полным значением.
- **Двойной щелчок** по «Станет» или «Новый путь» — правка на месте (Enter — принять, Esc — отмена).
- Ручная правка сильнее правила, ячейка подсвечена жёлтым. Пустое значение или «Вернуть по правилу» снимают правку. Правка пути задаёт и новое имя, правка имени меняет имя файла в пути. Ручная правка сама по себе включает переименование или перенос этой модели.
- Проверяется: в имени нет `\ / : * ? " < > |`, оно не зарезервировано Windows, не длиннее 255 знаков с `.rvt`; путь полный и оканчивается на `.rvt`; такой же новый путь не стоит у другой модели и не совпадает со старым путём другой модели из списка.

## 2. «Перепривязка связей»

Поля **«Старая папка»** и **«Новая папка»** («Обзор…» у каждого). «Из переноса» берёт «было/стало» папки с первой вкладки. Прогон только перепривязывает связи в отмеченных моделях, ничего не переименовывает и не переносит.

- Задание пишет `relink_map.csv` (`old_prefix;new_prefix`, UTF-8 с BOM). `update_rvt_links.py` заменяет префикс у связей, чей путь лежит в старой папке (граница по папке: `Стадия П` не совпадает со `Стадия ПП`); остальные связи не трогает. Новый путь сохраняет стиль слэшей исходного: UNC и диск с `\`, `RSN://` с `/`.
- Файл `relink_map.csv` создаётся при каждом сохранении такого задания и удаляется, если задание другое (в git не хранится).
- Пока идёт проход, окно читает `отчёты\_progress_ops.txt` и показывает по каждой модели «В очереди / Идёт / Готово / Частично / Ошибка / Без изменений», а в строке состояния «модель N из M (имя)».
- Relink запускается с `--worksets open_all`: `LoadFrom` падает на связи в закрытом рабочем наборе. Год Revit берётся из `servers.cfg` по хосту RSN-модели.

## 3. «Смена версии Revit»

Версию-источник выбирать не нужно: она определяется по моделям. Для `RSN://` — по хосту из `servers.cfg`, для сетевого файла — по `_Rxx` в имени (`…_R22.rvt` → 2022); без `_Rxx` сетевой файл просто открывает выбранная версия. В колонке «Версия сейчас» у каждой модели её год или причина, почему его нет (неизвестный сервер); модели разных лет в одном списке — красное «Разные годы в списке», запуска не будет (один запуск = одна версия Revit). В «Целевая версия» только версии новее найденной (из 2021–2025). Буфер на ПК — папка по умолчанию.

## 4. «Связи: добавить» и 5. «Рабочие наборы»

Список моделей сверху, рабочая часть снизу, разделитель двигается и запоминается. Год Revit отмеченных моделей стоит рядом со счётчиком под списком и определяется так же, как на вкладке 3 (Revit Server — по `servers.cfg`, сетевой файл — по `_Rxx` в имени, модели из открытого отчёта чтения — так же по их путям): «Revit 2022 (по моделям)». Если не вышло — красное «Год Revit не определён» или «Разные годы Revit в списке», причина у каждой модели в «Состоянии». Здесь Revit запускается для чтения и записи, поэтому сетевой файл без `_Rxx` тоже останавливает запуск. Общая строка действий: «Прочитать наборы и связи», «Полное чтение», «Открыть отчёт чтения…». «Открыть отчёт чтения…» доступна всегда: она загружает готовый CSV чтения и добавляет его модели в список вкладки.

- Вкладка 4, подвкладки: «Связи» (что куда вставить и в какой набор), «Коды разделов» (латиница → кириллица, `section_codes.csv`), «Маска имени» (`name_mask.cfg`). «Вставить связи» вставляет только связи.

### Вкладка 4 «Связи: добавить»: как вставить новые модели связями

1. Добавьте в список целевые модели (куда вставлять) и новые модели (что вставлять), отметьте их галочками.
2. Роль задаётся в колонке «Роль»: выделите одну или несколько строк (Ctrl / Shift), щёлкните ячейку «Роль» и выберите «новая» или «целевая» в выпадающем списке. Роль меняется у всех выделенных строк. Правая кнопка («Пометить как новые / целевые») тоже работает.
3. «Прочитать наборы и связи» (или «Открыть отчёт чтения…»). Строка состояния внизу всегда в одну строку; полный текст (путь к отчёту, пояснения) — во всплывающей подсказке над ней. Пары предлагаются сами, кнопки для этого нет: после чтения, после открытия отчёта, после смены роли, галочки или маски таблица «Связи» пересчитывается. В строке состояния — итог: «Пары: вставить N, уже есть N, нет пары N… Маска имени: …». Пока среди отмеченных нет ни одной модели с ролью «новая», таблица «Связи» пустая, а в строке состояния — «Отметьте новые модели в колонке «Роль».».
4. Правило автоматических пар: новая модель вставляется в целевые модели **того же корпуса** с другим разделом. Пример: целевая `SITE_ORG_EOM_K1_R22`, новые `HC_K1…K4`, `AVT_K1…K5`, `AVT_PRK` → вставятся `HC_K1` и `AVT_K1`, остальные 8 — «нет пары». «Нет пары» показывается только у новых моделей: целевая модель, в которую ничего не вставляется, в таблицу не попадает. Строки «нет пары» и «имя не разобрано» не мешают запуску: они просто не вставляются и перечислены в окне подтверждения в «Пропущено».
5. Связь вне правила (например, паркинг `AVT_PRK` в модель корпуса K1) добавляется руками: «Добавить связь вручную…» на подвкладке «Связи». Слева отметьте, куда вставить (выделенные в списке модели уже отмечены), справа — что вставить. Строка появится с пометкой «(вручную)», набор предлагается так же, как для автоматических. Ручные строки не пропадают при пересчёте (пока окно открыто и обе модели в списке), проверяются на «уже есть» / «другой путь» и уходят в тот же план. «Удалить строку» убирает выделенные ручные строки; автоматическая строка уходит, если снять галочку у модели или сменить её роль.
6. Набор для связи берётся из того, как уже названы наборы связей в целевой модели: `01_Связь_RVT_AR_K1` → для `HC_K1` предлагается `01_Связь_RVT_HC_K1`, для паркинга — `01_Связь_RVT_AVT_PRK` (раздел и корпус подставляются). Если наборы связей в модели названы по-разному, берётся вариант большинства; при равенстве ячейка пустая и подсвечена жёлтым. Пустой «Рабочий набор» бывает и тогда, когда наборы и связи целевых моделей ещё не прочитаны; строка состояния пишет: «Нет рабочего набора у N строк: прочитайте наборы и связи или введите имя.» Имя вводится прямо в ячейке: щелчок по ячейке «Рабочий набор», F2 на строке или двойной щелчок открывают поле ввода, Enter — сохранить, Esc — отмена. Строка без рабочего набора не вставляется: она попадает в «Пропущено» с причиной «нет рабочего набора». Недостающий рабочий набор создаётся при вставке.
7. «Вставить связи» открывает окно подтверждения: сверху одна фраза («В 1 модель будет вставлено 2 связи, будет создано 2 рабочих набора.»), ниже таблица «Модель», «Что вставить», «Рабочий набор», «Действие» (короткие имена, полный путь — во всплывающей подсказке; в «Действии» — «вставить» или «вставить + новый набор»; колонки по ширине текста), под ней — «Пропущено» с короткой причиной у каждой строки («нет рабочего набора», «нет целевой модели этого корпуса», «связь уже есть»; полное объяснение — во всплывающей подсказке строки). Кнопки «Вставить» (Enter) и «Отмена» (Esc) внизу справа видны всегда; окно подстраивается под экран, работает и в окне удалённого рабочего стола 1024×550, размер можно менять. До «Вставить» в модели ничего не пишется. «Пробный прогон» — то же окно с одной кнопкой «Закрыть»; нажимать его не обязательно. Revit открывает только модели, в которые что-то вставляется.
8. Вставленные связи закрепляются автоматически (Pinned) в той же транзакции, что и вставка. Если закрепить не удалось, связь остаётся, в отчёте результат OK с сообщением `not_pinned: <причина>`.

**Маска имени** — какая часть имени модели раздел, какая корпус. Порядок: роли, изменённые на подвкладке в этом сеансе → сохранённый `name_mask.cfg` (пересчёт его не трогает) → определение по таблице «Коды разделов» (часть, где стоят коды EOM, HC, AVT, АР…, — раздел; другая меняющаяся часть — корпус; одинаковые у всех части — «как есть»; если корпус у всех один, корпусом считается соседняя с разделом часть, кроме года вида `R22`) → прежняя догадка по новым и целевым именам. Роль части выбирается в выпадающем списке в ячейке «Роль» (раздел, корпус, как есть, не важен), «Запомнить маску» пишет её в `name_mask.cfg`. Под таблицей видно, откуда маска: «из name_mask.cfg», «по кодам разделов», «изменена вручную, не записана». Если маску определить не удалось или имя не подходит к ней, строки в «Связях» остаются с состоянием «имя не разобрано», а строка состояния говорит причину и отправляет на «Маску имени».
- Вкладка 5: фильтр «Модель:» и «Заменить в имени: … → …»; таблица «Модель», «Рабочий набор сейчас», «Станет» (двойной щелчок — правка), «Элементов» (пока «—»: чтение не считает элементы), «Действие». Удаление выбранных наборов: «перенести элементы в …» (набор по умолчанию, выбран сразу) или «вместе с элементами» (в «Действии» красное «удалить ВМЕСТЕ С ЭЛЕМЕНТАМИ»). Подвкладка «Связи в моделях (только просмотр)» — связи, которые уже стоят («Рабочий набор экземпляра», «Рабочий набор типа»). «Записать наборы» только переименовывает, создаёт и удаляет наборы.

## Буфер на ПК (смена года на RSN)

Revit новой версии не открывает старый Revit Server. Выгрузка с RSN на диск рабочего ПК с RBP: в RBP **Detach = ON**, Task = `detach_to_buffer.py`, список старых RSN. Это не боевая централь. Дальше новая Revit: `saveas_central.py` + `rvt_list_staging.txt`.

UNC→UNC с апгрейдом: буфер не нужен (Revit 2024 открывает файл 2022 на шаре и сразу SaveAs).

## RBP

В логе RBP только ASCII: `Output()` в `update_rvt_links.py` проходит через `ops_lib.ascii_safe` (остальное заменяется на `?`), так же текст исключений. Полные пути и кириллические имена попадают только в отчёты `отчёты\*.csv`.

Один запуск = одна версия Revit. Чеклист после Save job.

| Скрипт | Когда | Detach |
|--------|--------|--------|
| `detach_to_buffer.py` | старый RSN → файл на этом ПК | **ON** |
| `saveas_central.py` | новая централь (имя/папка/сервер) | OFF, Create New Local |
| `update_rvt_links.py` | прямые RVT Links по `job_paths` (полное имя пути) | OFF |
| `read_worksets.py` | чтение наборов и связей, без записи в модель | OFF, по умолчанию `--worksets close_all`; «Полное чтение» — `open_all` |
| `apply_workset_links.py` | переименование и создание наборов, вставка связей по общим координатам | OFF, `--worksets open_all` |

Вложенные связи не меняются из хоста — открывается каждая модель, которая сама держит связь.

### Чтение наборов и связей вручную

В окне это вкладки 4 и 5. «Прочитать наборы и связи» открывает модели с закрытыми наборами: так быстрее, но связи из закрытого набора могут не попасть в отчёт, а число элементов не считается. «Полное чтение» открывает все наборы. Дальше правка таблиц (роль «новая» у моделей нового раздела, маска набора, коды). «Вставить связи» / «Записать наборы» показывают план и по умолчанию ждут «Нет». После «Да» проход переименовывает наборы, создаёт недостающие и вставляет связи только по общим координатам. Если общие координаты не согласованы, строка пропускается, связь «начало к началу» не ставится. Пути — RSN и сетевые папки. Тот же проход чтения можно запустить вручную. На одной тестовой модели: текстовый файл с одним путём (RSN или UNC), Revit нужного года.

```
BatchRvt.exe --task_script "<папка>\служебное\read_worksets.py" --file_list "<список.txt>" --create_new_local --worksets close_all --revit_version 2024
```

Полное чтение — тот же вызов с `--worksets open_all`.

Скрипт чтения не открывает транзакцию, не сохраняет и не синхронизирует. Отчёт пишется в `отчёты\workset_read_<дата>.csv` (UTF-8 с BOM). Указатель на текущий файл: `отчёты\_active_workset_read.txt`. В отчёте все пользовательские наборы, включая «30_ИОС_Элементы», и связи: набор типа и набор экземпляра. Несовместная модель отмечена строкой `not_workshared`.

Запись из окна вызывает `apply_workset_links.py` (тот же список моделей, `open_all`, без detach). Порядок: переименование, создание набора, вставка связи. Каждая строка — своя транзакция. Связь ставится только `ImportPlacement.Shared`; если общие координаты не настроены, транзакция откатывается и в отчёте `SKIP_COORDS`. Вставленный экземпляр закрепляется (`Pinned = True`) в той же транзакции; если закрепить не удалось, связь остаётся, результат OK, сообщение `not_pinned: <причина>`. Отчёт: `отчёты\workset_apply_<дата>.csv`, указатель `отчёты\_active_workset_apply.txt`. Если менять нечего, синхронизации нет (`NO_CHANGES`).

После зелёного Pass 2: пункт **4** очистка старых моделей. UNC + буфер на ПК — переносятся в `_to_delete`; RSN — `to_delete_rsn.txt` в Admin.

Перенос UNC без смены имени и без апгрейда: пункт **3** (Windows Move), затем relink.

## Безопасность переноса и очистки

`delete_old_models.ps1` и `move_centrals.ps1` по умолчанию работают в режиме **dry-run**: печатают план и ничего не меняют. Применить можно только явно: `-Execute` (спросит `YES`) или `-Execute -Yes` (когда подтверждение уже получено, например в окне). `-DryRun` выигрывает у `-Execute`. Меню `служебное\run_cascade.cmd` (пункты 3 и 4) и `.cmd`-обёртки сначала делают dry-run и просят набрать `YES`.

Очистка старых моделей (`delete_old_models.ps1`):
- Ничего не удаляется: файл переносится в `<его папка>\_to_delete\<дата_время>\`, рядом `manifest.csv` с исходным путём. Откат — вернуть файл из этой папки.
- Модель переносится, только если отчёты прохода показывают `OK` (Pass 1: `saveas_central`, для RSN ещё `detach_to_buffer`; Pass 2: `update_rvt_links`, допустимо и `NO_CHANGES`) и новый файл есть и больше 0 байт. Отчёт должен быть новее `job_paths.csv`. `job.json` и `job_paths.csv` обязательны.
- Строки, где старый путь равен новому, не трогаются. Если одно новое имя встречается в задании несколько раз, а в отчёте Pass 2 в колонке `host` только имя без пути, такие модели пропускаются (штатный `update_rvt_links.py` пишет туда полный путь).
- Буфер на ПК переносится в карантин вместе с успешной строкой. RSN-модели только перечисляются в `to_delete_rsn.txt` (размер новой RSN-модели проверить нельзя).
- Содержимое `_to_delete` вы чистите вручную, пикеры моделей эти папки пропускают.

Перенос UNC (`move_centrals.ps1`):
- Без `Move-Item -Force`. Если файл назначения уже есть, строка пропускается (`SKIP_EXISTS`).
- `-Overwrite`: существующий файл назначения сначала переносится в `_to_delete`, потом на его место приходит перенесённый. В окне включается чекбоксом «Разрешить перезапись существующих файлов» (по умолчанию выключен), из `.cmd` — только вручную.
- После переноса проверяется наличие и совпадение размера.

SaveAs новой централи (`saveas_central.py`):
- Не перезаписывает существующий файл: `OverwriteExistingFile = False`, а для путей на диске/шаре дополнительно явная проверка. Если цель уже есть, модель получает статус `SKIP_EXISTS` в отчёте и не обрабатывается дальше (в самом Revit ничего не сохраняется).
- Перезапись включается только флагом `allow_overwrite` в `job.json` (чекбокс в окне, по умолчанию выключен). Читается именно булево `true`.
- Для RSN-цели существование заранее проверить нельзя: защита — `OverwriteExistingFile = False` и предупреждение в консоли RBP.
- Повторный прогон: `SKIP_EXISTS` после более раннего `OK` по той же модели считается успехом при очистке старых моделей, одиночный `SKIP_EXISTS` — нет.

Окно: перед переносом и очисткой старых моделей запускается dry-run, и показывается список («что будет перенесено / что пропущено и почему») с кнопками «Да» и «Нет». «Нет» — по умолчанию (Enter, Esc, крестик). Отказ от переноса останавливает прогон (следующие проходы зависят от перенесённых файлов); отказ от очистки просто пропускает её.

Тесты (без зависимостей, файлы `.ps1` в UTF-8 с BOM, иначе PowerShell 5.1 читает кириллицу как ANSI):
- PowerShell 5.1 или 7, каждый запуск: `powershell -NoProfile -ExecutionPolicy Bypass -File служебное\tests\<имя>.tests.ps1`, где `<имя>`: `paths` (раскладка папки и ссылки), `encoding` (BOM и разбор парсером всех `.ps1`), `psquirks` (нет `@(...)` над `List[object]` из `New-Object`: на 5.1 это падает с «Argument types do not match»), `safety`, `name_ops`, `ui_logic`, `preview_paths` (пути для всех режимов), `relink_job`, `start_ops`, `window_logic`, `move_tab` (поля вкладок «Перенос», «Смена версии», изолированные прогоны, пробный прогон: настоящие функции окна на заглушках, WinForms не нужен), `workset_logic`, `workset_ui`.
- Python (CPython, без Revit): `python -I служебное\tests\test_ops_lib.py`, `test_relink_prefix.py`, `test_rbp_ascii.py`, `test_script_dir.py` (папка данных для `.py` в новой раскладке), `test_workset_plan.py` (разбор CSV и путей, без Revit).
