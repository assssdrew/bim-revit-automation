# Выгрузка квартирографии v7 — инструкция

[English](INSTRUCTION.md)

Скрипт выгружает помещения квартир (совмещённый санузел, уборная, гардеробная) и помещения МОП (лестничная клетка, тамбур-шлюз, тамбур-шлюз (ПБЗ), коридор, лифтовой холл) из связанной модели АР **одного корпуса** в файл Excel. При открытии Excel сам находит одинаковые этажи, заполняет «Таблицу 1» и лист «МОП». В Revit ничего не меняется. Excel во время выгрузки не запускается: файл пишется напрямую, стандартной библиотекой Python (`zipfile` и XML).

Что нового в v7: площади до сотых (`AREA_DECIMALS = 2`); лист «МОП»; этажи в «Таблице 1» разделены линией и заливкой; у групп типовых этажей свои цвета (до 40); результат и ошибки — текстом в поле «Результат» Проигрывателя. Файла `…_ОШИБКА.xlsx` больше нет. Зависших процессов Excel от выгрузки нет.

## 1. Где что лежит

Папка скрипта — одна на все проекты. В этом репозитории путь-заглушка (подставьте свою папку):

`\\server\share\Dynamo\Выгрузка квартирографии`

| Файл | Что это |
|------|---------|
| `Выгрузка_квартирографии.dyn` | Граф Dynamo. Его запускают. |
| `Квартирография_ШАБЛОН.xlsx` | Шаблон отчёта. Не открывать для правки, не переименовывать, не удалять. |
| `Выгрузка_квартирографии.py` | Копия кода узла (для справки, для запуска не нужен). |
| `Инструкция_Выгрузка_квартирографии.docx` | Та же инструкция в Word. |
| `build.py` | Заново собирает шаблон. Для запуска не нужен. |
| `mk.py` | Заново собирает docx. Для запуска не нужен. |

Папка отчётов создаётся сама рядом с открытой моделью ОВ:

- Обычная модель: папка модели ОВ `\Квартирография`.
- Модель совместной работы: папка файла-хранилища `\Квартирография`.

| Файл в папке «Квартирография» | Что это |
|-------------------------------|---------|
| `Квартирография_K01.xlsx`, `…_K04.xlsx`, … | Отчёты по корпусам. Появляются после первой выгрузки корпуса. |
| `Квартирография_K01_старый_ДАТА.xlsx` | Копия отчёта v6. Создаётся один раз при первой выгрузке v7 в старый файл (в старом нет листа «МОП»). Можно удалить. |

В папке скрипта отчёты не появляются. Модель ОВ должна быть сохранена на диске или на сетевой шаре. Для модели в облаке (BIM 360 / ACC) и для Revit Server (`RSN://`) папку рядом создать нельзя.

Строка `SCRIPT_DIR` в узле Python должна указывать на папку скрипта, где лежит шаблон.

## 2. Первая настройка (один раз на компьютере)

1. Revit → вкладка «Управление» → «Проигрыватель Dynamo».
2. В окне проигрывателя нажмите значок папки («Изменить папку»).
3. Выберите папку скрипта (путь выше). Проигрыватель её запомнит, и «Выгрузка_квартирографии» останется в списке.

Если сетевой папки не видно в окне выбора:

- Откройте папку в Проводнике → правый клик по папке «Выгрузка квартирографии» → «Закрепить на панели быстрого доступа».
- Снова откройте выбор папки — она появится слева в «Быстром доступе».

Чтобы Dynamo не предупреждал о файле из сети: Dynamo → «Настройки» → «Безопасность» → «Доверенные расположения» → добавьте эту папку.

Единственный вход проигрывателя — «Связь АР». Выход «Результат» показывает текст прогона.

## 3. Выгрузка корпуса (каждый раз)

За один запуск выгружается один корпус (одна связь АР).

1. Закройте в Excel все файлы `Квартирография_*.xlsx`.
2. Откройте модель ОВ нужного корпуса. Связь АР загружена, модель сохранена.
3. «Управление» → «Проигрыватель Dynamo» → у строки «Выгрузка_квартирографии» нажмите запуск.
4. Дождитесь окончания и раскройте поле «Результат»: «ГОТОВО: корпус K04, Файл: …» и число выгруженных помещений. Если там «ОШИБКА: …» — см. раздел 7.
5. Откройте папку «Квартирография» рядом с моделью ОВ (для совместной работы — рядом с файлом-хранилищем) и файл `Квартирография_Kxx.xlsx`. Пример: `Квартирография_K04.xlsx`.

Номер корпуса скрипт берёт из имени связи АР. Пример имени (вымышленное): `PRJ_AR_01_K04_R24.rvt` → `K04`. Если папки или файла корпуса ещё нет, они создаются сами: файл — копией шаблона из папки скрипта.

Поле «Связь АР» оставьте пустым, если загружена одна связь АР. Заполняют его, только когда связей АР несколько (раздел 7).

Запускайте граф из Проигрывателя. Если открыть тот же граф в редакторе Dynamo и нажать «Запуск», не изменив код узла Python, редактор может не выполнить узел повторно и выгрузка не обновится.

## 4. Что смотреть в отчёте

| Лист | Что на нём |
|------|------------|
| Типовые этажи | Одинаковые этажи — один номер группы и один цвет (у каждой группы свой, до 40 групп). Справа — сводка по группам: группа, список этажей, количество. Вверху — дата и время выгрузки. |
| Таблица 1 | Этаж \| Номер \| Тип \| Комнат \| Sобщ \| Sж \| СУ \| Уборная \| Гардеробная. Каждый новый этаж отделён линией, этажи через один залиты серым. |
| МОП | Площади МОП по этажам: столбец на каждое имя из «Настроек», «Итого этаж» справа, «Итого корпус» в строке 3. |
| Выгрузка МОП | Сырые данные МОП (этаж, имя, площадь). Руками не править. |
| Выгрузка | Сырые строки квартир из Revit. Руками не править: при следующей выгрузке лист очищается и заполняется заново. |
| Настройки | Корпус, учёт типа квартиры, имена помещений квартир и МОП (раздел 6). |
| Инструкция | Краткая памятка внутри книги. |

Формулы пересчитываются при открытии файла (`fullCalcOnLoad`). При закрытии Excel может спросить «Сохранить изменения?» — можно ответить «Да». Площади выгружаются с точностью до 0,01 м².

## 5. Повторная выгрузка того же корпуса

Файл корпуса целиком не перезаписывается: листы «Выгрузка» и «Выгрузка МОП» полностью очищаются и заполняются заново, старых строк не остаётся. «Типовые этажи», «Таблица 1» и «МОП» пересчитываются по новым данным. Правки на листе «Настройки» сохраняются. Файлы других корпусов не затрагиваются: имя файла берётся из имени связи АР.

Перед запуском файл корпуса должен быть закрыт. Если он открыт, скрипт ничего не запишет и в «Результате» будет «Файл занят».

Формулы шаблона читают «Выгрузку» через `INDIRECT`, поэтому замена листа не превращает их в `#REF!`.

Первый прогон v7 по файлу v6 (в нём нет листа «МОП») переименовывает его в `Квартирография_<код>_старый_<дата>.xlsx` и создаёт новый файл из шаблона.

## 6. Новый объект или другие параметры АР

Имена помещений — на листе «Настройки» (формулы не трогать):

- В столбцах СУ / Уборная / Гардеробная перечислены варианты имён квартирных помещений. Если в АР помещение называется иначе (например, «С/у»), впишите вариант в пустую ячейку нужного столбца.
- Столбец «МОП» (F) — имена помещений МОП для листа «МОП», до 10. То же имя должно быть в списке `MOP_NAMES` скрипта.
- «Учитывать тип квартиры при поиске типовых этажей»: «нет» — сравниваются только наборы помещений; «да» — ещё и типы квартир.

Имена параметров в самом скрипте (если у АР другие параметры):

1. Откройте `Выгрузка_квартирографии.dyn` в Dynamo.
2. Двойной щелчок по узлу «Выгрузка АР».
3. Измените только блок НАСТРОЙКИ вверху. Строки `KLWT_*` — пример имён общих параметров одного заказчика:

```python
P_FLOOR = "KLWT_Этаж"                     # этаж
P_TYPE  = "KLWT_Тип квартиры"             # тип квартиры
P_NUM   = "KLWT_Номер квартиры на этаже"  # номер квартиры
P_SOBSH = "KLWT_Площадь квартиры общая"
P_SZH   = "KLWT_Площадь квартиры жилая"
ROOM_NAMES = ["Совмещенный санузел", "Санузел", "Ванная", "Уборная", "Туалет", "Гардеробная"]
MOP_NAMES  = ["Лестничная клетка", "Тамбур-шлюз", "Тамбур-шлюз (ПБЗ)", "Коридор", "Лифтовой холл"]
AREA_DECIMALS = 2                         # знаков после запятой
```

4. «Принять изменения», затем Ctrl+S.

Новое имя помещения (квартиры или МОП) добавляют в двух местах: в `ROOM_NAMES` / `MOP_NAMES` скрипта (иначе помещение не выгрузится) и на листе «Настройки» (иначе оно не попадёт в нужный столбец). Для новых корпусов правьте шаблон в папке скрипта (он общий для всех проектов), для уже созданных — их файлы в папке «Квартирография».

Новый объект копировать не нужно: скрипт один, отчёты ложатся рядом с открытой моделью ОВ. Если папку скрипта перенесут, поправьте `SCRIPT_DIR` в блоке НАСТРОЙКИ и сохраните граф.

## 7. Ошибки и что делать

Все сообщения выводятся текстом в поле «Результат» Проигрывателя Dynamo.

| Что видно | Что делать |
|-----------|------------|
| ОШИБКА: Загружено несколько связей АР … | Впишите в поле «Связь АР» часть имени нужной связи, например `K04`, или выгрузите лишние связи («Управление связями» → «Выгрузить»). Скрыть связь на виде недостаточно. Сравнение не зависит от регистра, разделителей и парных букв кириллица/латиница. |
| ОШИБКА: Загруженная связь АР не найдена … | Загрузите связь АР («Управление связями» → «Обновить/Загрузить») или впишите часть её имени в поле «Связь АР». Ниже в сообщении — список связей модели. |
| ОШИБКА: Файл занят: … закройте его | Файл корпуса открыт в Excel. Закройте и запустите снова. Если он нигде не открыт — Диспетчер задач → завершить `EXCEL.EXE`. |
| ОШИБКА: Нет шаблона … | Шаблон удалили или переименовали, либо `SCRIPT_DIR` ведёт не туда. Проверьте, открывается ли папка в Проводнике. |
| ОШИБКА: Модель ОВ не сохранена | Сохраните модель ОВ и запустите снова. |
| ОШИБКА: Модель ОВ хранится в облаке / на Revit Server | Папку отчётов рядом с такой моделью создать нельзя. Откройте модель, сохранённую на сетевом диске. |
| ОШИБКА: Не удалось создать папку отчётов … | Нет прав на запись в папку модели ОВ (или файла-хранилища). |
| ВНИМАНИЕ: нет параметров в связи … | Поправьте имена параметров в блоке НАСТРОЙКИ (раздел 6). |
| ВНИМАНИЕ: пропущено помещений без этажа/номера | В АР у этих помещений не заполнен этаж или номер квартиры. |
| В отчёте нули или пусто | Проверьте, что в АР заполнены параметры из блока НАСТРОЙКИ и имена помещений совпадают с листом «Настройки». |

## 8. Ограничения

- Excel для выгрузки не нужен. Он нужен, чтобы смотреть отчёт.
- За один запуск выгружается один корпус (одна связь АР).
- Лист «МОП»: до 10 видов помещений; этажи — числа (`01`, `1`, `2` …). МОП с нечисловым этажом в лист не попадёт.
- Цвета групп повторяются, только если групп больше 40.
- До 15 квартир на этаже, 80 этажей, 1500 квартир, 3000 строк выгрузки на корпус.
- Макросов нет. Файл `.xlsx` открывается в Excel 2010 и новее.
- Скрипт только читает помещения связи АР. Модель ОВ он не сохраняет и не синхронизирует. На диск он пишет папку «Квартирография» и файл корпуса.
