# Кейс 05 — Сжатие workshared-моделей (Compact)

[← К хабу](../../README.ru.md) · [EN](README.md)

## Проблема

Хранилища Revit раздуваются после месяцев синхронизаций. Нужная галочка Autodesk — **«Сжать файл»** в Сохранить / Синхронизироваться с хранилищем, это не zip и не «Очистить неиспользуемые». Вручную: год Revit, открыть хранилище (или новый локальный), сжать, Sync, Relinquish, закрыть — и так по папке или Revit Server.

## Решение

Операторское окно (`Сжатие.vbs` → WinForms). Человек выбирает модели (файлы / папки / `RSN://`), режим, жмёт «Сжать». Toolkit сам раскладывает список по годам Revit и гоняет API-задачу; [Revit Batch Processor](https://github.com/bvn-architecture/RevitBatchProcessor) — только хост батча.

| Режим | Когда | Что делает |
|-------|--------|------------|
| **Быстрый** | По необходимости; команда может оставаться в файлах | Create New Local, закрыть наборы, `SynchronizeWithCentral` с **Compact = True**, Relinquish. |
| **Глубокий** | Раз в месяц / квартал | Открывает **хранилище с Audit** (без нового локального, без Detach, наборы закрыты) → Сохранить как **то же** хранилище со сжатием → Sync Compact. |

Excel (листы «Модели», «Сводка», «Динамика»): вес до / после, сводка прогона, динамика к прошлым отчётам. Экономия места разная: часто очень маленькая (например 61,03 → 61,01 МБ на прогоне из двух моделей); на отдельных моделях больше (до примерно −11,6% на одной ранней модели в быстром режиме).

## Масштаб / контекст проекта

| | |
|--|--|
| Статус | Проверено на рабочих моделях; глубокий RSN — на ограниченном числе прогонов |
| Эффект | В среднем примерно в 4–5 раз быстрее, чем вручную; длинные списки (например ~125 моделей) в одном незанятом прогоне; изменение размера разное (часто маленькое, например 61,03→61,01 МБ; до примерно −11,6% на одной ранней модели в быстром режиме) |
| UX | Одно окно; в списке можно смешивать диск, UNC и `RSN://`; годы идут очередью |
| Пишет в модель? | **Да** — Compact хранилища (workshared) или Save Compact (обычный `.rvt`) |

## Безопасность

- Compact — это **запись**. Глубокий режим = окно обслуживания: бэкап, предупредить команду, никто не синхронизируется во время прогона.
- Быстрый: Create New Local, Detach **OFF**.
- Глубокий: открытие хранилища + Audit; живое хранилище не Detach. Окно спрашивает, продолжать ли, прежде чем открыть хранилище и пересохранить его. Оно не проверяет, что другие закрыли свои локальные файлы.
- Глубокий режим RSN требует патч RBP v4 (`служебное/rbp_rsn_patch`, маркер `RSN_PATCH_PS_v4`). Окно пытается поставить его в локальный RBP. Стоковый RBP делает Detach. Глубокий RSN проверен на ограниченном числе прогонов.
- Не сжимать резервные / датированные копии (например, `RVT\Backup\…`) — путь к живому хранилищу может быть неверным. Код пропускает пути с `Backup`, датированной папкой или папкой «Резерв».
- Это не Purge Unused и не zip `.rvt`.

Подробнее: [docs/SAFETY.ru.md](../../docs/SAFETY.ru.md)

## Запуск

1. Скопировать `src/` на ПК с Revit и RBP
2. Прописать хосты в `servers.cfg` (в этом репо — заглушки)
3. Дважды щёлкнуть `Сжатие.vbs`
4. Добавить модели → Быстрый или Глубокий → Сжать
5. Первый запуск Revit: если BatchRvt блокируется — `служебное\разрешить_надстройку_BatchRvt.cmd`

Файлы `.ps1` в этом кейсе специально в **UTF-8 с BOM**. Windows PowerShell 5.1 без BOM ломает кириллицу.
